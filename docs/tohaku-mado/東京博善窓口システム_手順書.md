## 1. システム全体の繋がり

「東京博善の窓口（mado）」は、**東京博善株式会社**の7斎場（**町屋斎場・落合斎場・代々幡斎場・四ツ木斎場・桐ヶ谷斎場・堀ノ内斎場・お花茶屋会館**）で、葬儀当日の**受付・火葬同意・飲食などの注文・会計精算**をデジタル化するシステムです。

**繋がっているシステム**

| 相手 | 何をやり取りするか |
|---|---|
| 新予約システム（テコテック製・9月稼働。旧 Fellow／タイコウ） | 毎朝、当日の火葬予約データを受け取る（中間サーバー経由） |
| LINE | お客様向けの接続（ミニアプリ・通知）として作られていますが、**使用しません**。通知は届かない前提で、ご案内は口頭と紙で行います |
| SAP（基幹システム・広済堂 情報システム部管理） | 商品カタログを受け取り、注文を「受注」として登録。割引（社員割・区民葬など）や仕訳も自動処理 |
| 自動精算機（東芝テック／ユニコ） | 管理画面で発行する「精算QR」を読み取り、お客様が支払い |
| PDA（スタッフ携帯端末） | 売上計上に使用 |
| 会員情報登録API（OutSystems） | 火葬予約の会員情報を外部システムへ登録する連携（§3.8の「🧾 会員情報登録API 送信先」で送信のON/OFFと送信先を管理。連携OFFの間は呼び出されません） |

**一つ一つのシステムの役割（詳しく）**

**① 新予約システム（テコテック製）** — 火葬予約の大元です。

窓口はここから**中間サーバー経由で予約データを受信するだけ**の参照側で、窓口の「📅 予約」タブから新規予約を作ることはありません（作成・変更は予約システム側で行い、窓口へは10〜15分程度の時間差で届きます — §3.5）。

届いた予約を「確定」することで、受付・精算に使えるようになります。

**② 中間サーバー（NURVE管理）** — 窓口とSAP・予約システムの間に立つ通訳役です。商品カタログ・カート・受注・精算機の入金連絡は全てここを経由します。

SAPへの送信がタイムアウトした時に「届いたかは不明」という表現になるのは、窓口→中間→SAPの2段構えのため、途中まで届いている可能性があるからです（だからこそ**再送の前に注文一覧・カートの確認**が必要になります）。

**③ SAP（基幹システム・広済堂情報システム部管理）** — 商品マスタ・得意先マスタ・受注・請求の正本です。

窓口の商品・得意先・割引可否・受注ブロックは全てSAPから同期した写しで、**金額の最終的な正はSAP側**にあります。

画面の金額とSAPの金額が食い違うと「⚠ 金額照合待ち」などで会計が止まる仕組みです（§3.7）。

**④ 自動精算機（東芝テック／ユニコ）** — 精算QR（SAP受注番号入り）を読み取ってお客様が支払う機械です。支払いが完了すると中間サーバー経由で窓口に入金の連絡が届き、受付と注文が自動でお会計済みに進みます。

処理が途中で止まった場合は15分で自動解除され、急ぐ時だけ「精算ロック管理」を使います（§3.7⑪）。

**⑤ LINE** — お客様向けの接点（ミニアプリ・通知）として作られた接続ですが、**使用しません**。通知は届かないため、進行・お支払いのご案内は口頭と紙（自動精算機ご利用票）で行います。

この運用は現行の画面に既に備わっているもので、特別な設定は不要です（§3.7「🖨 紙で受付」・「🖨️ 印刷」）。

**⑥ PDA（スタッフ携帯端末）** — 売上計上の端末です。窓口とは直接繋がっておらず、「PDAで計上してから『💳 お会計精算へ移す』を押す」という**操作の順序**で整合を取ります。

**番号の呼び分け（取り違えの多い3つ）**

| 番号 | どこで使うか |
|---|---|
| **予約番号** | 新予約システムから届く番号（例: TEST-2500200 / 25087953）。管理画面の検索欄は**全て「予約番号」表記**です。注文カードでは 🔑 のマークで表示されます |
| **SAP受注番号** | 「💳 お会計精算」で「💰 支払い準備完了」を押したときにSAPが発行する番号（例: 783）。**精算QRはこの番号で発行**されます |

**運用の要点**

- 予約・注文・受付の画面は**リアルタイム更新**です（新しい注文が入ると通知音が鳴ります）。
- SAPへの連携は**2段階**です。①「🍽️ オーダー」で注文を **お会計準備完了** に進めると（ボタンは「💳 お会計精算へ移す」）、SAP側の**カートに蓄積**されます（カードに「🛒 カート蓄積済」と表示）。

    ②「💳 お会計精算」で **💰 支払い準備完了にする** →「支払い内訳確認」→ **💰 支払いお知らせを送信** まで進めた時点で、**SAPの受注（受注番号）が発行**されます。

- ご注文は全て「📝 代理注文」（§3.3）で承ります。送信でタイムアウトが出た時は、**再送の前に必ず注文一覧・カートを確認**します（二重投入防止の基本です）。
- 検証環境（STG）は**テスト専用**です。実際のお客様のデータは入れません。テストデータは予告なくリセットされることがあるため、確認結果は都度スクリーンショット等で保存して下さい。

## 2. 業務の全体像 — 斎場職員の一日の流れ

この章では、火葬日前日までの準備と火葬当日の運用を、**斎場職員の一日の流れ**に沿って説明します。**お客様にスマホの操作をお願いする場面はありません** — 受付・注文・会計は全て職員が管理画面で行います。

「いま何の場面で、どのタブを開き、何を押すか」をこの章で掴み、ボタンごとの詳しい説明は第3章を参照して下さい。

### 2.1 前日まで — 準備の流れ

担当: 本社・斎場管理者 → 斎場スタッフ

**1.【管理者】予約の確定（→§3.5）** — 「📅 予約」タブで翌日分を確認し、「未確定」ボタンから確定します。確定の画面で区民葬・献体・減額・公費の該当と、支払先の葬儀社（得意先）を確認します。

**確定は受付より先に**行います（順序が逆になると受注が二重に作られるケースがあります — §3.5）:

![予約タブで翌日分を確定する](imgs/a12-reservations.png)

![予約の確定画面（割引と得意先の確認）](imgs/a13-rsv-confirm-modal.png)

**2.【スタッフ】翌日の全体像の確認（→§3.6）** — 「📋 火葬確認」の日付を翌日に切り替え、件数・火葬開始時間の並び・葬儀社を確認します。

火葬同意はお客様のLINE操作では頂かない運用のため、画面の「承諾/未承諾」表示に関わらず、同意のお手続きは紙の様式など決められた方法で準備します（様式・保管の方法は運用の案内に従って下さい）。

### 2.2 当日の朝 — 始業チェック

担当: 斎場スタッフ全員（画面を使う人それぞれ）

朝、管理画面を開いたら、業務を始める前に**ヘッダーの5点**を確認します（→§3.1）。

| # | 確認すること |
|---|---|
| 1 | **表示対象日が本日**になっているか（前日の履歴を見た後の戻し忘れに注意） |
| 2 | **斎場が自斎場**になっているか（一覧・件数・通知の全てがここに連動します） |
| 3 | **通知音が🔔ON**か（OFFだと新規注文に気付けません） |
| 4 | ヘッダーに「**リアルタイム接続中**」が出ているか（「❌ 接続エラー」のままなら再読込） |
| 5 | 表示が古そうなら **Ctrl+Shift+R** で最新化 |

![画面上部（ヘッダーとタブ）](imgs/a69-tabs-strip.png)

<img src="imgs/btn/c-topbar-date.png" width="360"> <img src="imgs/c-topbar-right.png" width="420">

（左: 表示対象日の切り替え ／ 右: 利用者・斎場・通知音・ログアウト）

続いて「📋 火葬確認」を開き、**本日の火葬予約の全体像**（何件あるか・火葬開始時間の並び・どの葬儀社か）を掴みます:

![本日の火葬予約が火葬開始時間順に並ぶ（火葬確認）](imgs/a14-checkins.png)

あわせて「🚪 部屋紐付け」で本日使う控室・休憩室の状態（空き・紐付け済み）を確認しておきます:

![部屋紐付けの一覧（本日の部屋の状態）](imgs/a10-room-assignments.png)

### 2.3 ご到着〜炉前 — 受付と火葬同意

担当: 受付・炉前のスタッフ

ご到着されたら、「📋 火葬確認」で該当のご葬家の行（喪家名・葬儀社・火葬開始時間）を確認します。**火葬同意は紙のお手続きで頂きます**（お客様のスマホ操作はお願いしません。様式は運用の案内に従って下さい）。

画面の「承諾/未承諾」のバッジは使いません（同意の有無は紙のお手続きで確認します）。

受付の操作は「💳 お会計精算」で行います。

カードの「**✅ 受付する**」でご来場を受け付け（→§3.7①）、喪主の行が「QR待ち」表示の時は紫の「**🖨 紙で受付**」を押します — 「喪主を紙で受付します。（LINEなし）続けますか？」の確認でOKすると、**LINEなしで喪主様の受付が完了**し、以降の会計を通常どおり進められます（→§3.7①-2）:

<img src="imgs/btn/y-pair-paper.png" width="360">

LINEに紐付かないため、この後の進行・お支払いの通知は届きません。お呼び出し・ご案内は全て口頭と紙で行います。

### 2.4 控室へのご案内 — 部屋紐付け

担当: フロア・配膳のスタッフ

ご家族を控室・休憩室へご案内する前に、「🚪 部屋紐付け」で該当の部屋に予約を紐付けます。紐付け画面では**一覧の行そのものをタップ**すると確定します（→§3.4）:

![予約の割り当て（行をタップで確定）](imgs/a11-ra-assign-modal.png)

既に別のご予約が紐付いている部屋では上書きの警告が出ます。前のご家族の利用が終わっているかを確認してからOKして下さい:

![上書きの警告](imgs/a39-ra-overwrite-warning.png)

紐付けはご注文・ご提供の管理の土台になります（代理注文のフリードリンク判定・お届け先の部屋の特定に使われます）。ご注文はお部屋へ伺って承り、「📝 代理注文」で入力します（→§2.5）。

### 2.5 火葬中〜お食事 — 注文対応

担当: 売店・厨房・配膳のスタッフ

**ご注文は全て職員が「📝 代理注文」で入力します**（→§3.3）。

お部屋・売店で伺った内容を入力すると、「🍽️ オーダー」の4つの列（未処理 → 調理中 → 提供済み → お会計準備完了）にカードとして現れ、進行を管理できます。新しい注文は通知音でお知らせします:

![オーダー画面（4つの列で注文を進行管理）](imgs/a01-orders-kanban.png)

代理注文の入力は、予約のあるご家族・葬儀社の手配は 予約を選ぶ → 商品を選ぶ（購入者は葬儀社払いで自動確定。喪主払いにする分は後から「📋 注文詳細」で振り分け）、予約のないお連れ様のその場購入は「🚶 予約なし」→「お連れ様購入」です（→シナリオD）:

![代理注文（予約を選んで商品を選ぶ）](imgs/a48-proxy-step2-payer.png)

![予約なしの購入者選択（葬儀社・喪主・お連れ様）](imgs/a50-proxy-step2-norsv.png)

オーダーのカードは、場所ラベル（📍月の間1・売店レジ前 など）で**どこへ届けるか**を確認し、「調理開始」→「🍽️ 提供済み」→（PDAで売上計上）→「💳 お会計精算へ移す」の順に進めます（→§3.2）:

![注文カード（場所ラベル・明細・進行ボタン）](imgs/c-order-card.png)

画面上部の「📤 SAP受注」の帯に**⚠失敗**が出ていないかを時々確認し、出ていたら理由を確認して再送します（→§3.2⑨）:

![SAP受注の帯（失敗が出ている状態）](imgs/c-sap-chips.png)

### 2.6 収骨前〜お見送り — 会計・精算

担当: 会計担当のスタッフ

お食事が落ち着いたら「💳 お会計精算」で会計を進めます。

流れは **✅ 受付する →（🏷 割引・🏷 振り分け）→ 💰 支払い準備完了にする → 支払い内訳確認 → 💰 支払いお知らせを送信 → 🏧 精算QRを発行 → 自動精算機でお支払い → 🏁 会計完了にする** です（→§3.7）:

![お会計精算（会計待ち→会計完了で管理）](imgs/a17-payment-kanban.png)

葬儀社とご喪家で支払いを分ける場合は、先に「🏷 振り分け」で品目ごとの支払先を決めます。区民葬などの割引もこの段階で確定させます:

![品目振り分け（一括ボタンで支払先を割り当て）](imgs/a51-assign-modal.png)

![割引設定（葬儀社ごとの対応可否と連動）](imgs/a30-discount-modal.png)

「💰 支払い準備完了にする」を押すと「支払い内訳確認」が開きます。金額と警告を確認して「💰 支払いお知らせを送信」— この瞬間にSAPの受注番号が発行されます（この番号で精算QRを発行します）:

![支払い内訳確認（内訳と警告を確認して送信）](imgs/a76-payment-start-modal.png)

送信後のカードには「支払先ごとの受注」の枠が現れます。**未払いの受注だけ**に精算QRのボタンが出るので、受注ごとにQRを発行します（売掛の受注は請求書回収のため対象外）:

![支払先ごとの受注（未払いだけ精算QRを出せる）](imgs/y-sap-orders-box.png)

![精算QR画面（税込金額が確定した受注）](imgs/a64-priceqr-ok.png)

精算QRは「🖨️ 印刷」で**《自動精算機ご利用票》として印刷し、紙でお渡しします**。お客様はご利用票のQRを自動精算機で読み取ってお支払いになります。お支払いの確認が取れたら「🏁 会計完了にする」で締めます:

![自動精算機ご利用票（QRとお支払金額入り・これを紙でお渡しする）](imgs/a52-settlement-slip.png)

### 2.7 ご利用終了後 — 締めと翌日への引き継ぎ

担当: フロア・受付のスタッフ

- **部屋の解除** — お見送りが済んだら「🚪 部屋紐付け」で「解除」を押します（忘れると次のご家族が注文出来ません — §3.4②）。
- **オーダーの残り確認** — 「お会計準備完了」列に残っているカードが無いか、SAP帯に⚠失敗が残っていないかを確認します。
- **翌日の準備** — §2.1（予約の確定・翌日の全体像の確認・同意の紙様式の準備）を翌日分に対して行います。
> **「受付」と「注文」は別の操作です。** 受付＝「火葬確認」タブで来場を受け付ける操作。注文＝「代理注文」タブでスタッフが商品を注文する操作。

**🔍 一つ一つの操作の詳しい流れ（オーダー）**

**① 👨‍🍳 調理開始** — 調理が必要な商品（天ぷらそば・うどんなど温かい食事）を受けた時に、厨房へ取り掛かりの合図をするための操作です。

押す前に、カードの商品明細と場所ラベル（どのお部屋からの注文か）を確認します。

押すとカードが「調理中」列へ移るだけで、**お客様への通知は届きません**（調理中の通知は仕組みとしてありません）。

飲み物だけの注文など、調理が要らない場合はこのボタンを押す必要はなく、次の「🍽️ 提供済み」へ直接進めて構いません。押し間違えた場合は「← 未処理に戻す」で戻せます。

**② 🍽️ 提供済み** — 商品をお客様のお手元へ届け終えた時に押します。押した瞬間にカードが「提供済み」列へ移ります。

お渡しの記録を正しく残すため、**実際にお渡ししてから**押して下さい。複数の注文をまとめてお届けした場合は、届けた注文のカードを1枚ずつ押します。

**③ 💳 お会計精算へ移す** — お渡しが済んだ注文を会計の待ち行列に載せる操作で、**PDAで売上計上を済ませた後**に押すのが順番です。

押すと2つのことが同時に起きます: (1) カードが「お会計準備完了」列へ移り、注文の内容が**SAPのカート（会計の入れ物）に蓄積**されます（受注番号はまだ発行されません — 発行は「💳 お会計精算」タブの「💰 支払い準備完了」で行われます）。

(2) なお、ご予約に紐づかないスポット注文ではボタンが「**→ お会計準備完了**」になり、**働きも異なります**（SAPへは送られません — ご注文時に受注確定済みのため。下の「スポット注文の扱い」参照）。

**押した結果が確認できなかった時の表示** — 通信の不調などで、カートに入ったかどうか確認できないまま終わることがあります。

その場合は次のように表示されるので、**共通して「再送せず、まず注文詳細でカートの中身を確認する」**を徹底して下さい（そのまま再操作すると二重投入の恐れがあります）:

- 「SAPカートへの到達結果が未確定です。精算待ちへ移さず、SAPカートを確認してください。」
- 「精算への移動の応答待ちがタイムアウトしました。SAP側は処理を継続している可能性があります。再操作せず、［注文詳細］→［SAP診断］でSAPカートの状態を確認してください。」
- 「ステータスは変更しましたが、SAPへの送信結果が確認できませんでした。カートに入ったかは不明です。注文詳細でSAPカートを確認してから対応してください（そのまま再送すると二重投入になる可能性があります）。」

また、複数の注文を「全て提供済みに」でまとめて進めた時に一部のSAP送信が失敗していると「⚠ 提供済みにした注文のうち ◯件のSAP送信に失敗しました。このまま進むと支払いお知らせ前のSAP失敗ゲートで確認を求められます。［注文詳細］→「↻ SAP再送」で再試行できます。」と表示されます。

会計の前にここで解消しておくと、支払い準備完了がその分すんなり通ります。

**④ 💰 お会計済み** — 売店などで**その場で現金等のお支払いが完了した**注文だけに押します。押すとカードは右上の「お会計済み」件数に集計されます。

**喪主まとめ払いの注文では絶対に押さないで下さい** — まとめ払いは「💳 お会計精算」タブで一括精算するのが正しい流れで、ここで押してしまうと精算対象から外れてしまいます。

また、SAPの金額確認が必要な注文では、このボタンの代わりに「⚠ SAP金額照合待ち」と表示されて押せません（§3.7の「🔄 SAPと照合」で確認してから進めます）。

**⑤ ← 戻すボタン（未処理に戻す／調理中に戻す／提供済みに戻す／お会計準備完了に戻す）** — 押し間違えた時に、カードを1つ前の列へ戻すための操作です。

戻しても**既に送られたお客様への通知は取り消せません**（例: 提供済みを取り消しても「提供が完了しました」の通知は届いたままです）。戻した後は正しい順序でもう一度進めて下さい。

**⑥ ✕（注文の取り消し）** — 「未処理」列のカードにだけ付いています。注文そのものを取り消す操作です。

調理が始まった後（調理中以降）の取り消しは、この✕ではなく「✏️ 編集」での一部取消か、列を未処理へ戻してからの取り消しになります。取り消しのご依頼をお客様から受けた場合も、スタッフがこの操作で対応します。

**⑦ ✏️ 編集（一部キャンセル）** — 「1品だけ取り消したい」「数量を間違えた」時の操作です。

開いた画面で行の「✕」を押すと合計金額がその場で再計算され、消し過ぎた時は「＋ 商品を追加」で商品名・品番から戻せます。最後に「保存」を押すまで確定しません。

**編集出来るのはSAPカートへ入る前（お会計準備完了へ移す前）まで**で、投入後は「SAPカート投入後の注文は編集できません」と表示されます。その場合の内容変更は§3.7側（注文詳細・SAP照合）で扱います。

**編集を保存した時の結果表示** — カートに入り始めている注文の編集は、保存と同時にSAPカート側の品目の入れ替えまで行われます。

結果は次の3通りの表示で必ず知らされるので、**表示を読んでから**次の操作に進んで下さい:

| 表示 | 意味と対処 |
|---|---|
| 編集内容をSAPカートへ反映しました | 正常終了。そのまま進めます |
| 編集は保存しましたが、SAPカートへの反映に失敗しました。「↻ SAP再送」で復旧してください | 画面上の注文は直りましたが**カート側は古いまま**です。案内どおり「↻ SAP再送」で復旧します |
| 保存結果を確認できませんでした。注文一覧を再読み込みして状態を確認してください(そのまま再操作しないでください) | 通信が途切れて結果が不明の状態です。**再操作すると入れ替えが二重に走る恐れ**があるため、必ず再読込で状態を確かめてから対応します |

**⑧ 📋 注文詳細** — 予約番号の単位で、その方の全注文の明細・金額・支払先の振り分け・SAP連携の状況をまとめて確認する画面です。

会計の前に「どの品目を誰が支払うか」を確認・変更したい時はここを開きます（振り分けの詳しい操作は§3.7）。確認だけなら何度開いても状態は変わりません。

**⑨ ↻ SAP再送・📋 送信内容・↻ 失敗分を一括再送** — SAP連携に失敗した注文（⚠SAP失敗の赤いバッジ）を送り直す操作です。

押す前に必ずバッジにカーソルを合わせて**失敗理由の全文**を確認して下さい（例:「代表品目分類 "17" の支払割当が見つかりません」→ 先に振り分けを直さないと再送しても同じ失敗になります）。

「📋 送信内容」ではSAPに送った内容そのものを確認出来ます。失敗が複数ある時は画面上部の「↻ 失敗分を一括再送」でまとめて再送できます。

**「⚠ SAP未確定」（到達が確認できていない）の注文だけは、そのまま再送すると二重投入の恐れがある**ため、先に「📋 注文詳細」でカートの中身を確認してから判断して下さい。

**🔬 さらに深く（オーダー画面 — 裏側の動きと例外）**

各操作の「画面で見える動き」の裏で何が起きているか、うまくいかない時に何を疑うかを、要素ごとに1段深く整理します:

| 要素 | 裏で起きていること | 例外・注意 |
|---|---|---|
| 注文カードが現れる | 「📝 代理注文」で送信した注文が登録され、進行管理の対象になります | ご案内は全てお声がけで行います（お客様への自動通知はありません） |
| 「🍽️ 提供済み」を押す | カードの列が「提供済み」に変わり、お渡し済みの記録になります | 列は「← 調理中に戻す」で戻せます。お渡しの実態と列を揃えるため、押すのはお渡しと同時にします |
| 「💳 お会計精算へ移す」を押す | SAPのカート（会計の入れ物）に品目が積まれ、お会計準備の通知が届きます。**受注番号はまだ発行されません** | カート投入の結果が確認できないことがあります（③の3分類）。共通の対処は「再送せず、注文詳細でカートを確認」です |
| 「💰 お会計済み」を押す | 支払い完了として記録されます | 喪主まとめ払いのご家族では**押しません**（受付単位の精算は§3.7側で行うため。個別に押すと二重会計の元になります） |
| 「↻ SAP再送」を押す | 失敗した注文の内容を、SAPカートへもう一度積み直します | 「⚠ SAP到達不明」だけは**届いているのに失敗表示**の可能性があり、そのまま再送すると二重投入になり得ます。必ず先にカートの中身を確認します |
| 「✏️ 編集」で保存する | カートに入り始めた注文は、保存と同時に**カート側の品目の入れ替え**（旧品目を外して新品目を入れる）まで行われます | 入れ替えの結果は3分類の表示で知らされます（⑦）。結果不明の時に再操作すると入れ替えが二重に走る恐れがあります |

**🧾 スポット注文の扱い（予約にも受付にも紐付かない注文）**

「🚶 予約なし」から入力した代理注文・お連れ様購入など、**予約にも受付にも紐付かない注文**は、通常の注文と会計の仕組みが根本的に異なります。

- **SAP連携のタイミングが違います。**

    通常の注文は「お会計準備完了」でカートに蓄積→「💰 支払い準備完了」で受注確定、という2段階ですが、スポット注文は**ご注文を送信した時点で、その注文だけで完結する受注としてSAPへ確定**します（カートには積まれません）。

- **「💳 お会計精算」タブには載りません。** 受付単位で精算するお会計精算の対象外のため、カードに「**🧾 スポット注文（お会計精算の対象外）**」のバッジが付き、「💳 お会計精算へ移す」ボタン自体が表示されません（代わりに「→ お会計準備完了」が出ます）。
- **会計はこのオーダー画面内で完結させます。** お渡し・PDA計上の後、「→ お会計準備完了」→ その場でお支払いを受けて「💰 お会計済み」の順に進めます。
- **お渡しとお会計は口頭でご案内下さい**（お客様への自動通知はありません）。
- **お連れ様購入には「G」で始まるゲスト予約番号**が自動で発行され、カードと成功表示（「✅ お連れ様注文を作成しました 予約番号: G…」）に表示されます。領収書や後からの照会はこの番号で行えます。

**🔍 一つ一つの操作の詳しい流れ（代理注文）**

**① ⚙️ 斎場・売上場所設定（STEP 0）** — 「どこの売上として計上するか」を最初に決める操作で、ここが未選択の間は下のステップが全て塞がっています。

毎回同じ場所で入力する方は「デフォルト保存」を押しておくと、次回からログインした時点で自動的に選ばれた状態になります。

**売上場所を間違えたまま注文を送ると、後の精算でエラーになる**事例が報告されているため（誤った売上場所でも入力自体は通ってしまいます）、送信前にもう一度設定バーの表示を確認して下さい。

**② 🔍 紐付け（予約番号で選ぶ）** — 予約番号が手元にある場合の最短ルートです。

入力して押すと、その場で予約が検索され、成功すると「✅ 予約紐付け完了: 東博　太郎」と表示され、紫のバッジ（予約番号・故人名・葬儀社名）が付きます。

番号の打ち間違いなどで見つからない場合はエラーが表示されるだけで、何も確定しません。選び直したい時はバッジの「✕」を押します。

**③ 📋 予約一覧から選ぶ** — 番号が分からない時に使います。本日の予約が一覧表示され、故人名・葬儀社・予約番号で検索、葬儀時間順の並び替えが出来ます。行を選ぶとその予約に紐付き、②と同じ状態になります。

受付（チェックイン）が完了している予約は、葬儀社の得意先が自動で入っています。

**④ 🚶 予約なし（スポット注文）** — ご予約と関係のないスポット購入（お連れ様の追加の飲み物など）の入り口です。これを選んだ時だけ「2 購入者を選択」が開き、**誰のお支払いになるか**を必ず選びます。

葬儀社（→得意先の選択欄が開く。**売掛が使えない葬儀社では売掛の注文は送信前に止まります**）・喪主（直売）・お連れ様（SAP即連携＝その場精算）から選択します。

**スポット注文は送信した時点でSAPへ受注として確定し、「💳 お会計精算」タブには載りません**（オーダー画面内で「→ お会計準備完了」→「💰 お会計済み」と進めて完結。§3.2「スポット注文の扱い」参照）。

予約なしで送った注文は後から予約に紐付けられないため、ご予約のある方の注文と分かっている場合は必ず②か③で予約を選んでから進めて下さい。

**④-2 お連れ様購入の流れ（詳しく）** — 購入者で「🚶 お連れ様」を選ぶと、お名前・領収書名・ラベルを添えられます（お名前が未入力の場合は「お連れ様」で登録されます）。

商品を選んで「**🚶 お連れ様購入（SAP即連携）**」を押すと、**その瞬間にSAPへ受注が確定**し、「✅ お連れ様注文を作成しました 予約番号: G…」と表示されます（**Gで始まるゲスト予約番号**が自動採番され、領収書やお問い合わせの手掛かりになります）。

作成された注文は最初から「お会計準備完了」列に入るので、お支払いを受けて「💰 お会計済み」で完結します。

送信中に通信が切れた場合は「送信の結果が確認できませんでした（通信タイムアウト）。SAPに届いたかは不明です。再送する前に必ず注文一覧を確認してください」と表示されます — **必ず注文一覧を確認してから**再送して下さい。

前回の送信が実は成立していた場合は、再送時に「⚠ 前回の送信が既に注文として成立しています。注文一覧を確認してください」と自動で止まる仕組みも入っていますが、確認が先です。

**④-3 酒類を含む注文の記録** — ビール・日本酒など酒類を含む代理注文・お連れ様購入を確定すると、**職員が年齢と運転の有無を口頭で確認したものとして記録**されます（確認した職員のアカウントが監査記録に残ります）。

必ず口頭確認をしてから確定して下さい（ノンアルコール商品は対象外です）。

**⑤ 商品を選んで「注文を送信」（STEP 3）** — 商品カードの「＋／−」で数量を調整すると、画面下部に合計金額が積み上がります。

絞り込み（大分類・商品名・品番など）は表示を絞るだけで、カートの中身には影響しません。

購入者によって出せる商品が自動で変わる点に注意して下さい: お連れ様には一般商品のみが表示され、喪家向け商品（精進料理膳など）やスタッフ代理専用品（骨壺など）は自動的に隠れます。

購入者を途中で変更すると、その購入者に出せない品目はカートから外され、件数と理由が画面に表示されます。

「注文を送信」を押すと確定し、「🍽️ オーダー」タブの「未処理」列に新しいカードが現れます（以降の進行は§3.2と同じです）。**送信は1回だけ**押し、応答を待って下さい（最大45秒。§1参照）。

タイムアウトの表示が出た場合は「届いていない」と決めつけず、**先に注文一覧で前回分が入っていないかを確認**します — 同じ内容をもう一度送っても、前回が成立していた場合は「⚠ 前回の送信が既に注文として成立しています」と自動で止まる仕組みが入っています。

**注文の補足情報（任意）** — 商品一覧の上に、ラベル（例: 机1）・注文者名・領収書の宛名の入力欄があります。領収書の宛名は、空欄の場合は喪家名などから自動で設定されます:

![注文の補足情報（ラベル・注文者名・領収書の宛名）](imgs/a110-proxy-note-fields.png)

**入力時に止まる主な表示** — 1品目の数量は999個までです（「1品目あたりの上限は999個です」）。

金額をその場で決める**任意金額の商品**は、商品カードに「任意金額」と表示され、金額（税抜）の入力欄が付きます。金額を入れずに送信しようとすると「任意金額品目の金額（税抜）を入力してください: ◯◯」で止まります:

![任意金額の商品カード（金額の入力欄付き）](imgs/a111-proxy-manual-price.png)

前のご注文のカートが残ったまま別の予約を選ぶと「前の伝票の商品がカートに残っています。「−」で外すか、STEP1の ✕ でやり直してください」と案内されます（同じ予約のまま続けて入力する場合は「📦 カートの商品 ◯件を保持しました」とカートが引き継がれます）。

**⑤-2 送信した後に出る結果表示（重要）** — 「注文を送信」の後には、**注文の成立**と**SAP連携の結果**が1つのメッセージで知らされます。「✅ 代理注文 #◯」だけなら正常です。

「作成しましたが、…」と続く場合は注文自体は成立しており、**SAP側だけが未解決**の状態なので、メッセージ別に次のように対応します:

| 表示（「代理注文 #◯ を作成しましたが、…」に続く部分） | 意味と対処 |
|---|---|
| SAPに送る品目がありません（SAP品目コード未設定）。この金額はSAPに請求されません。 | 商品マスタに品目コードが無い商品でした。**請求漏れになる**ため、商品マスタを確認して正しい商品で入れ直します |
| SAP連携に失敗しました。この金額はSAPに請求されません。注文詳細の「↻ SAP再送」で解消してください | 通信・登録の失敗。案内どおり「↻ SAP再送」で解消します |
| SAPへの到達が確認できていません（未確定）。再送せず、注文詳細でSAPカートの内容を確認してから対応してください。 | 届いたかどうか不明の状態。**再送は二重投入の恐れ**があるため、必ず先にカートを確認します |
| SAPへの送信結果が確認できませんでした。カートに入ったかは不明です。 | 同上（通信タイムアウト）。注文詳細でカートを確認してから対応します |
| SAP連携が無効のため送信されていません。この金額はSAPに請求されません。 | SAP連携の設定が無効になっています。管理者に確認します |

**⑤-3 売掛・葬儀社に関する制限で止まる表示** — 葬儀社のお支払い条件によっては、送信前に次の表示で止まることがあります:

- 「🚫 この葬儀社はブロック中です（◯◯）。受付できません。」— 得意先マスタで受注ブロック中の葬儀社です（§3.8の「ブロック同期」参照）。
- 「この葬儀社は売掛にできません。現金を選んでください」／「この葬儀社は売掛にできません（現金は選べます）」— 売掛が使えない葬儀社です。現金でご案内します。
- 「この葬儀社は分類 ◯ を売掛にできないため送信できません（◯件）」— 一部の品目分類だけ売掛に出来ない契約です。該当品目を現金側へ分けるか、外して送信します。
- 「この葬儀社が売掛にできない分類（◯）の商品 ◯件をカートから削除しました」— 売掛不可の品目が自動でカートから外された通知です。外れた商品を確認して下さい。

**⑤-4 振り分け未設定でカートに入れられない時（ゲスト切替の提案）** — 紐付き注文をSAPカートへ入れる際、支払振り分けが未設定だと確認が出ます。

文面は「⚠️ この注文はカートに追加できません。原因: 支払振り分けが未設定のため 【対応方法】① 受付タブで「🏷 振り分け」を設定後に再送 ② ゲスト購入として単体送信 — ゲスト購入に切り替えますか？」です。

**OKするとその場でスポット注文（単体受注）に切り替わり**「ゲスト購入に切り替えました。SAP送信を再試行します...」と続行されます。受付単位でまとめて精算したい場合はOKせず、先に振り分けを設定して下さい。

**⑥ 送信した後の支払先の直し方** — 予約ありの代理注文は自動的に「葬儀社払い」で登録されます。

喪主様のお支払いにしたかった場合は、送信後に「🍽️ オーダー」の「📋 注文詳細」を開き、支払先を「喪主」へ振り分け直します（§3.2⑧・§3.7）。注文を送り直す必要はありません。

**🔬 さらに深く（代理注文 — 裏側の動きと例外）**

| 要素 | 裏で起きていること | 例外・注意 |
|---|---|---|
| ①でご予約を選ぶ | 予約から葬儀社（得意先コード）が取り込まれ、購入者が「🏢 葬儀社払い」で自動確定します（②が飛ぶのはこのため） | 予約に得意先コードが無いと自動確定できず、②購入者選択が開きます（画面右下に案内が出ます） |
| 「注文を送信」を押す（予約あり） | 注文が登録され、オーダーの「未処理」列に載ります。SAPへはこの時点では送られません（お会計準備完了でカートへ） | 応答は最大45秒。**送信は1回だけ**。同じ内容を誤って再送しても、前回が成立していれば自動で止まります |
| 「🚶 お連れ様購入（SAP即連携）」を押す | その瞬間にSAPへ**単独の受注**が確定し、Gで始まるゲスト予約番号が採番されます（後からの照会の鍵） | 送信＝受注確定のため、内容の間違いは取り消し・修正の手間が大きくなります。押す前の読み合わせが特に重要です |
| 酒類を含めて確定する | 職員が年齢・運転の口頭確認を済ませたものとして、確認者のアカウントつきで監査記録に残ります | 記録は自動です — **必ず実際に口頭確認をしてから**確定して下さい（ノンアルコールは対象外） |
| 購入者を途中で変更する | その購入者に出せない品目が自動でカートから外され、件数と理由が表示されます | 外れた品目は戻りません。必要なら購入者を確定した後に選び直します |

### 3.4 🚪 部屋紐付け（部屋と予約の紐付け）

**出来ること:** 控室・休憩室・式場・ラウンジ・お別れ室の部屋にご家族の予約を紐付けます。紐付けは、ご注文のお届け先の部屋の管理と、休憩室の**フリードリンクの出し分け**の土台になります。

![部屋紐付け（月の間1が紐付け中）](imgs/a10-room-assignments.png)

![部屋の行の拡大（残り時間のカウントダウン付き）](imgs/c-room-rows.png)

| ボタン・表示 | 説明 |
|---|---|
| <img src="imgs/btn/r-btn-assign.png" height="36"> | **紐付け** — 部屋に予約を割り当てる（下の画面が開く） |
| <img src="imgs/btn/r-btn-release.png" height="36"> | **解除** — 「紐付けを解除しますか？」の確認が出て、OKすると解除されます。ご利用終了時に必ず押して下さい（紐付け中の部屋にだけ表示されます） |
| <img src="imgs/btn/r-btn-reload.png" height="36"> | **再読込** — 一覧を最新化 |
| <img src="imgs/btn/r-fd-badge.png" height="30"> | **FD制御** — この売り場でフリードリンクの出し分けが有効という印 |

「紐付け」を押すと「予約を紐付け」画面が開き、当日の予約から選べます（**故人名・申込者名・予約番号**で検索、「⏱ 葬儀時間」で並び替え）。

**一覧の行そのものをタップ**すると紐付けが確定します（確定用のボタンはありません）:

![予約の割り当て](imgs/a11-ra-assign-modal.png)

「期限切れ」の紐付けが残っている部屋では、上書きの警告が出ます（**有効な紐付け中の部屋には「紐付け」ボタン自体が出ません** — 下の「上書きは出来ない仕様」参照）:

![上書き警告](imgs/a39-ra-overwrite-warning.png)

| # | ご利用開始〜終了の手順 |
|---|---|
| 1 | ご家族を部屋にご案内する前にこのタブを開く |

| 3 | お客様をご案内し、部屋のQRを案内（予約にフリードリンク対象の品目があれば自動でフリードリンクメニューが出ます） |
| 4 | ご利用終了時に「解除」を押す（忘れても残り時間で自動失効し、表示は「期限切れ」に変わります。ただし失効するまでの間は次のご家族が注文出来ないため必ず解除して下さい。**「期限切れ」になると解除ボタンは消えます**） |

> **売店は部屋紐付けの対象外**です（ラストオーダーの対象外のため、紐付けなしで常時ご注文いただけます）。フリードリンクの出し分けを設定出来るのは**休憩室のみ**です。

**🔍 一つ一つの操作の詳しい流れ（部屋紐付け）**

**① 紐付け** — 「この部屋を、今からこのご家族が使う」とシステムに登録する操作です。

押すと「**予約を紐付け: ◯◯（売上場所名）/ ◯◯（部屋名）**」の画面が開き、当日の予約一覧から**行そのものをタップ**した瞬間に確定します（「確定」ボタンはありません。タップ＝確定なので、行を選ぶ前に故人名・葬儀社名をよく確認して下さい）。

一覧の各行には **故人名・葬儀時間・葬儀社・予約番号** が表示され、右側に3種類のバッジが付きます。行を選ぶ判断材料にして下さい:

| バッジ | 意味 |
|---|---|
| 🏢 葬儀社CK済（緑） | この予約の葬儀社受付（チェックイン）が済んでいます |
| ⏳ 待機中（黄） | 予約は確定済みですが、葬儀社の受付はまだです |
| 📦 ◯品目（黄） | この予約に予約品目（火葬料金など）が登録されています |

確定した瞬間から、その部屋に貼ってあるQRを読み取ったお客様がメニューを開けるようになり、残り時間（既定30分）のカウントダウンが始まります。

予約にフリードリンク対象の品目が含まれていれば、休憩室ではフリードリンクメニューが自動で表示されます。

**上書きは出来ない仕様です** — 残り時間内の（有効な）紐付けがある部屋には「紐付け」ボタンが表示されず、「解除」だけになります。

**付け替えは「解除」してから改めて紐付ける**のが正しい手順です（誤って別の予約に上書きしてしまう事故の対策）。

「期限切れ」の紐付けが残っている部屋だけは「紐付け」が押せ、その場合は「⚠ 現在「◯◯」が紐付け中です。確定すると上書きされます。」の注意と、確定時の「既存の「◯◯」を上書きして「◯◯」を紐付けますか？」の確認が出ます。

**同じ予約を別の部屋に紐付け直した場合**（お部屋の変更）は、完了時に「**部屋を付け替えました。旧部屋のQRは利用できません**」と表示されます。

1つの予約が同時に使える部屋は1つで、**前の部屋のQRは自動で使えなくなります** — 部屋を移られたご家族には新しい部屋のQRをご案内して下さい。

**② 解除** — ご利用終了時に「この部屋は空きました」と登録する操作です。押すと「紐付けを解除しますか？」の確認が出て、OKすると即座に解除され、その部屋のQRからは注文出来なくなります。

**解除を忘れても残り時間が切れれば自動失効しますが、失効するまでの間は次のご家族がその部屋から注文出来ません**。お見送りが済んだら忘れずに押す運用にして下さい。

表示が「期限切れ」に変わった部屋では解除ボタン自体が消えます（もう解除する必要が無いためです）。

**③ 残り時間（ラストオーダー）の見方** — 紐付け中の部屋の行には、**故人名と🏢葬儀社名**、残り時間が「分:秒」（例: 29:45）で表示され、**1秒ごとに減っていきます**。

この時間がそのままラストオーダーとして働き、切れた後にお客様がQRから注文しようとすると「ただいまこのお部屋ではご注文いただけません」と表示されます。

ご利用が長引く場合は、一度解除してから改めて紐付けると時間がリセットされます。標準の30分は「⚙️ 設定 → 初期設定」の「**🚪 注文場所・部屋紐付け 設定**」で変更出来ます（管理者のみ。→§3.8の画像参照）。

**④ 再読込** — 他の端末で行われた紐付け・解除を含めて一覧を最新の状態にします。一覧は**30秒ごとに自動でも更新されます**が、フロアの担当が複数いる時は、操作の前に一度押す習慣にすると行き違いを防げます。

**⑤ 一覧が空・エラーの時** — 「画面上部の斎場セレクタで斎場を選択してください」は斎場が未選択の状態です。

「この斎場には紐付け対象の部屋がありません」は、この斎場の売上場所に部屋が登録されていない状態で、画面の案内どおり**売上場所管理から部屋の登録**が必要です（管理者へ依頼）。

紐付け画面で「予約の取得に失敗しました」と出た場合は、画面を閉じてもう一度開き直して下さい。

部屋の一覧は**売上場所ごと**にまとまり、フリードリンクの出し分けが有効な売り場には「[FD制御]」の印が付きます。

**🔬 さらに深く（部屋紐付け — 裏側の動きと例外）**

| 要素 | 裏で起きていること | 例外・注意 |
|---|---|---|
| 行をタップして紐付ける | 部屋のQRとご予約が接続され、その瞬間からQRを読んだお客様にメニューが開きます。予約のフリードリンク対象品目の有無もこの時に判定されます | タップ＝即確定（確定ボタンなし）。選び間違えたら「解除」→ 正しい予約で紐付け直します |
| 残り時間の表示 | 期限は**サーバー側の時刻**で管理され、画面は1秒ごとに残りを表示し直しています（端末の時計のズレの影響を受けません） | 期限が切れると、その部屋あてのご注文の受付は締め切りの扱いになります |
| 「解除」を押す | 部屋とQRの接続がその場で切れます。データが消えるわけではなく、注文・会計の記録はそのまま残ります | 解除を忘れても自動失効しますが、**失効までの間は次のご家族が使えません** |
| 同じ予約を別の部屋で紐付ける | 紐付けが新しい部屋へ**移動**し、前の部屋は自動で空きます（1予約=同時1部屋） | 前の部屋のQRはその瞬間から使えません — お部屋を移られたご家族には新しいQRをご案内します |
| 一覧の更新 | 30秒ごとに自動で最新化され、他の端末での紐付け・解除も反映されます | 30秒の間は他端末の操作が見えていない可能性があります。操作の直前に「再読込」を押すのが確実です |

### 3.5 📅 予約（予約の確認・確定 — 管理者のみ）

**出来ること:** 新予約システムから毎朝届いた予約データを確認し、「確定」します。確定時に区民葬・献体・減額・公費の該当と、支払先の葬儀社（得意先）を確認します。

> **予約データの反映には10〜15分程度の時間差が出ることがあります。**
>
> 予約システム側で登録・更新した直後にこの画面へ表示されなくても、すぐに異常と判断せず、少し時間を置いてから再読込して確認して下さい（2026-09-14 操作説明会での周知事項）。
>

**🔍 一つ一つの操作の詳しい流れ（予約）**

**① 未確定 → 確定** — 予約システムから届いたデータを「この内容で受付・精算に使ってよい」と承認する操作です。

「未確定」ボタンを押すと確定の確認画面が開き、**区民葬・献体・減額・公費の該当**と**支払先の葬儀社（得意先）**を目視で確認してから確定します。

確定するとボタンが「✅確定」の状態表示に変わり、この予約が火葬確認・お会計精算の対象として流れ始めます。確定は取り消しの操作が無い前提で、**内容を確認してから**押して下さい。

また**受付が先に済んでいる予約を後から確定すると受注が二重に作られるケース**が報告されているため、順序（確定→受付）を守って下さい（冒頭の注意参照）。

**② ⚠ 葬儀社 未選択** — 予約に葬儀社の得意先コードが入っていない警告です。このままでも確定は出来ますが、**代理注文の自動確定（葬儀社払い）とSAP連携で支払先を決められず**、後の工程で必ず詰まります。

「✏️ 予約の編集」を開き、「🔍 葬儀社名から候補を出す」で得意先コードを設定してから確定して下さい。

**③ ✏️ 予約の編集** — 氏名・電話・住所などの申込者情報のほか、得意先コード・割引フラグ（区民葬・献体・減額・公費）・葬儀日・火葬日・火葬時間を修正出来ます。

画面下部の「🏗 施設予約情報（手動入力）」（予約パターン・炉種別・号炉・時間帯・火葬種別）、「⚱ 収骨容器（骨壺）選択」、「📦 予約品目」（SAP品目コード・品名・数量を「＋追加」で登録）まで一続きの画面です。

**ここで登録した予約品目が、お客様の「予約カート」と会計時のSAP連携の対象**になるため、火葬料金・式場使用料など最初から決まっている品目はここで揃えておきます。保存すると即時に反映されます。

**③-2 実施済みのご予約は「参照モード」になります** — 受付やお支払いが進んだ（実施済みの）予約の編集画面は、**金額とSAP受注の突き合わせに影響する項目がロック**された参照モードで開きます。

ロックされるのは 割引フラグ（区民葬・献体・減額・公費）・予約品目・葬儀社（得意先コード）・予約番号・葬儀日・火葬日・火葬時刻・施設予約枠（火葬炉枠・式場枠・骨壺・保管枠）・斎場・故人名 です — これらを実施後に書き換えると、確定済みのSAP受注と突き合わせが出来なくなるためです。

一方、**電話番号・住所・メールアドレス・申込者名など金額に影響しない事務項目**は、「**📇 事務項目だけ保存**」ボタンで実施済みでも更新出来ます（「事務項目（連絡先など）を保存しました」）。

ロック項目を含めて保存しようとすると「実施済のため参照のみです。連絡先など事務項目は「📇 事務項目だけ保存」から更新してください」または「以下は実施済のため保存されません: ◯◯」と案内されます。

**④ 絞り込みと並び替え** — 「対象日」（葬儀日・火葬日・式場利用日・保管期間のいずれかが重なる期間）と「状態」（全て／未確定／確定済み）、キーワード検索（故人名・葬儀社・予約番号・申込者・電話）で一覧を絞り込みます。

**⑤ 🗑 範囲クリア／🗑️ 本日分クリア（現在は非表示）** — テストデータ整理用の**削除操作**で、過去に誤操作でテストデータ61件が消えた事故があったため、**現在の画面ではどちらのボタンも非表示**になっています。

通常運用では使いません。

**⑥ ⚠ タイコウ不一致（予約システム側の変更との食い違い）** — 確定済みの予約は、後から予約システム側でデータが変わっても**自動では上書きされません**（確定した金額の根拠が勝手に変わるのを防ぐロック）。

その代わり、食い違いが起きたことがカードの「⚠ タイコウ不一致 (◯)」の印で知らされます。

どちらが正しいかを確認のうえ、予約システム側の値を採用する場合は「**📋 タイコウ値で編集モーダルを開く**」を押すと、受信した値が入った状態で予約の編集画面が開くので、内容を確認して保存します（**押しただけでは保存されません** — 編集画面で保存して初めて反映されます）。

**⑧ 予約の新規作成・リスト読込（現在は非表示）** — 予約をこの画面から直接作る「新規予約」、CSV・Excelから一括登録する「📥 予約リスト読込」、CSV出力・時間補完の各機能は、**日次運用で使わないため現在の画面からは撤去（非表示）**されています。

機能自体は残っており、必要な場合はシステム担当が実施します。

正規の予約は必ず新予約システム側で登録して下さい — この画面から臨時に作成した予約は予約システム側には反映されません。

**🔍 一つ一つの操作の詳しい流れ（お会計精算）**

**① ✅ 受付する** — ご来場を受け付けて、この方の会計を「会計待ち」の列に載せる操作です。押す前にカードの喪家名・葬儀社名・火葬同意バッジ（承諾/未承諾）を確認します。

押すとカードが会計待ちに並び、以降の割引・振り分け・精算の起点になります。

誤って受付した場合は「▼ 詳細」の「← 精算未受付に戻す」で戻せます（**「💰 支払い準備完了」を押す前まで**）。

**①-2 🖨 紙で受付（喪主がLINEを使えない時）** — カードの喪主の行（👤）には、喪主様のLINE連携の状態が「✅ LINE連携済」または「QR待ち」で表示されます。

**「QR待ち」のまま（＝喪主様がQRを読み取れない・LINEをお使いでない）場合は、紫の「🖨 紙で受付」ボタン**が出ます。

押すと「喪主を紙で受付します。（LINEなし）続けますか？」の確認が出て、OKすると**LINEなしで喪主様の受付が完了**し、以降の会計（振り分け・精算QR・ご利用票の紙渡し）を通常どおり進められます。

LINEに紐付かないため、この方への通知は届きません — お声がけと紙のご利用票でご案内下さい。

**② 🏷 振り分け（品目振り分け）** — 「どの品目を誰が支払うか」を決める操作で、**「💰 支払い準備完了」より前に済ませておくのが原則**です。

開いた画面で品目グループごとに支払先（葬儀社〈現金〉・葬儀社〈売掛〉・喪主・**💰 直売**）を割り当てます。

「💰 直売」を選んだグループには**直売得意先コード（数字6〜10桁）の入力欄**が開き、未入力のままだと画面下の集計に「⚠ 直売得意先コード未入力◯件」と表示されて確定出来ません。

売掛が使えない葬儀社では「🏢 葬儀社（売掛）」の選択肢自体が表示されません。

画面下の集計（👤 喪主 ¥◯ / 🏢 現金 ¥◯ / 🏢 売掛 ¥◯ / 💰 直売 ¥◯）で金額の割れ方を確認してから確定します。

全品目が同じ支払先なら上部の一括ボタン（「全て👤 喪主」「全て🏢 葬儀社（現金）」「全て🏢 葬儀社（売掛）」）が最速です。

割り当てたら必ず「✅ 振り分けを確定」（画面によっては「💾 振り分けを保存」）を押して下さい — 未保存の間は「✏️ 未保存の変更があります」と表示され、保存すると「✅ 振り分けを保存しました」と出ます。

「未設定」のまま送信すると**葬儀社払い〈現金〉として扱われ**、SAP側に既に支払割当があるカートでは登録に失敗します。

**受注が確定した後は振り分けの変更は出来ません**（ボタンが押せなくなり理由が隣に表示されます）。

**③ 🏷 割引（割引設定）** — 区民葬・献体・減額・公費の割引を適用する操作です。開くと現在の割引と選べる選択肢が表示されます。

選択肢は**葬儀社（得意先）ごとの対応可否と連動**しており、使える割引が無い葬儀社では「割引種別が見つかりません」と表示されます。

適用済みの割引を外す時は「🚫 割引なし（解除）」を押します。割引は金額の根拠になるため、**支払い準備完了の前に**確定させて下さい。

割引額の決まり方・確定後の内訳の読み方・キャッシュバックとの違いは、この節の下の「**🏷 割引と業者キャッシュバック（詳しく）**」にまとめています。

**④ 💰 支払い準備完了にする（支払い内訳確認 → 💰 支払いお知らせを送信）** — 会計の中心となる操作です。

押すと確定前に「**支払い内訳確認**」画面が開き、葬儀社払い（現金）と喪主支払い（現金）の金額・合計（税抜）・品目グループ内訳・警告が表示されます。

ここで金額が想定どおりかを必ず確認し（警告が出ている場合は下の警告一覧表に従って先に解消）、「**💰 支払いお知らせを送信**」で確定します。

確定した瞬間に、(1) **SAPに支払者ごとの受注番号が発行**され、(2) カードの大きいボタンが「🏁 会計完了にする」に変わって「▼ 詳細」の中に精算系のボタンが現れます。

内訳が違っていた場合は「🏷 振り分けを変更」からやり直せます（送信前まで）。

**⑤ 🏧 精算QRを発行** — お客様が自動精算機でお支払いになるためのQRを画面に出す操作です（「▼ 詳細」の中・SAP登録成功後に表示）。

税込金額が確定している受注は緑色で金額とQRが表示され、「精算QRを発行（税込 ¥◯◯）」で確定します。

税込金額を確定出来ない受注では黄色の警告が出て発行出来ません（先に「🔄 SAPと照合」）。発行後は「🖨️ 印刷」で《自動精算機ご利用票》（A4・QRとお支払金額入り）を印刷してお渡し出来ます。

**売掛の受注はここには出ません**（自動精算機の対象外・月次のご請求書で回収）。

**⑥ 📩 支払いQRを再送** — LINE連携のあるお客様へ精算QRを送り直すための操作です。

**使用しない運用では押しません** — 精算QRのご案内は「🏧 精算QRを発行」→「🖨️ 印刷」の紙のご利用票で行います。

**⑦ 🧾 支払確認** — 自動精算機でのお支払いが済んだかどうかをその場で照会する操作です。精算機からの入金の連絡は通常自動で届きますが、「お客様は払ったと仰っているのに画面が変わらない」時に手動で確認出来ます。

**⑧ 🏁 会計完了にする** — お支払いの確認が取れた後に押す締めの操作です。押すとカードが「会計完了」列へ移り、この方の会計が締まります。

「⚠ 金額照合待ち」「⚠ SAP照合待ち」が表示されている間は押せません — 先に「🔄 SAPと照合」等で解消します。

押した後に誤りに気付いた場合は「← 会計待ちに戻す」で戻せますが、精算処理の進行中は「🔒 精算未受付に戻せません」と表示されます。

**⑨ 🔄 SAPと照合／↻ SAP再送** — 「🔄 SAPと照合」は、画面の金額とSAPの受注金額・割引条件を突き合わせて食い違いを解消する操作です（⚠金額照合待ち・⚠SAP照合待ち・精算QRの金額不一致の時に使います）。

「↻ SAP再送」はSAP連携をやり直す操作で、**「⚠ SAP到達不明」の状態では先に「📋 注文詳細」でカートの内容を確認してから**再送して下さい（そのまま再送すると二重投入の恐れがあります）。

SAP照合の結果入力は管理者（superadmin）の権限が必要です — スタッフの画面では案内が表示されるので管理者へ連絡して下さい（§5）。

**⑩ 🧾 領収書分割（受注分割へ）** — 領収書を分けたい時の**案内**を開くボタンで、分割そのものはこの画面では行いません。

開くと対象のSAP受注番号と「🔀 受注分割やり直し画面を開く」ボタンが表示され、分割は外部の受注分割やり直し画面で行います。

既に分割済みの場合のみ「🗑 分割を解除して領収書1枚に戻す」で画面から戻せます。分割やり直し画面のURLが未登録の場合は管理者に「⚙️ 初期設定 → SAP連携設定」での登録を依頼して下さい。

**⑪ 🔒 精算ロック管理** — 自動精算機が処理の途中で止まった時の非常用の操作です。**15分経てば自動解除される**ため、通常は待つだけで構いません。

急ぐ場合のみ、「外部受注ID（予約番号など）」と「得意先コード」の2つを入れて「🔍 状態確認」→ 解除対象・理由・斎場コードを選んで「🔓 ロック解除」の順で使います。

SAP受注番号しか分からない時の「SAP受注番号で直接解除」は状態を確認しないまま解除する最終手段なので、**別の端末で精算中でないことを必ず確かめてから**実行して下さい。

**🔒 精算ロック管理の使い方**（精算機で処理が中断し、15分の自動解除を待てないときだけ使用）

![精算ロック管理に外部受注IDと得意先コードを入力した状態](imgs/a72-lock-filled.png)

| # | 操作 |
|---|---|
| 1 | 「外部受注ID」に予約番号などを、「得意先コード」（例: 900000）を入力して「🔍 状態確認」 |
| 2 | 状態が表示されたら、**解除対象**（精算のみ／キャッシュバックのみ／精算・キャッシュバック両方）・**理由**（通信断で残留／誤操作／その他）・**斎場コード**（例: YT）を選び、必要に応じて理由の詳細を記入 |
| 3 | 「🔓 ロック解除」を押す |

> SAP受注番号しか分からない場合は「**SAP受注番号で直接解除**」に進めますが、この場合はロック状態を確認しないまま解除することになります（画面にも「⚠ ロック状態は確認できていません」と表示されます）。
>
> **別の端末で精算中でないことを必ず確認してから**実行して下さい。
>
> 精算機が途中で止まった場合は15分で自動解除されます。二重会計防止のため、精算機側での二重操作はしないで下さい。

**🔬 さらに深く（お会計精算 — 裏側の動きと例外）**

| 要素 | 裏で起きていること | 例外・注意 |
|---|---|---|
| 「✅ 受付する」 | ご来場が記録され、以降の割引・振り分け・精算がこの受付に積み上がっていきます | 結果が確認できない通信エラーの時は**再操作せず再読込**（受付が出来ていれば列に現れます） |
| 「🏷 振り分け」を保存する | 「どの品目分類を誰が払うか」の割り当てが受付に記録され、SAP登録時の**支払割当**の元になります | 未設定のまま送ると葬儀社払い（現金）扱い。SAP側に既に割当があるカートでは**必ず失敗**します（支払い内訳確認が事前に警告します） |
| 「💰 支払いお知らせを送信」 | 支払者ごとに**SAPの受注番号が発行**され、カードに精算系のボタンが現れます — 会計の分岐点です | 以降、割引・振り分けは変更不可になります |
| 「🏧 精算QRを発行」 | 受注番号が入ったQRが作られ、自動精算機はこのQRで**SAPに金額を照会して**請求します | 税込金額が未確定の受注は発行できません（先に「🔄 SAPと照合」）。売掛の受注はQR対象外（月次請求で回収） |
| 精算機でお支払い | 入金の連絡が自動で届き、受注の行が「✅ 支払済み」に変わります | 反映には少し間が空くことがあります。「お客様は払ったと仰っている」時は「🧾 支払確認」で手動照会します |
| 「🏁 会計完了にする」 | 支払い完了が記録され、カードが「会計完了」列へ移ります | 「⚠ 金額照合待ち」「⚠ SAP照合待ち」の間は押せません。押した後の「← 会計待ちに戻す」で**精算機の入金は取り消されません** |
| 「🔒 精算ロック管理」 | 精算機の処理が途中で止まった時の残留ロック（精算・キャッシュバックの2種類）を解除します | **15分で自動解除**されるため、通常は待つだけ。急ぐ時も、別の端末で精算中でないことを確かめてから解除します |

#### 📋 注文詳細パネルでのカート品目の修正（詳しく）

「📋 注文詳細」を開くと、SAPカートの品目が1行ずつ表示されます。

**まだSAPに送信していない品目**（カート編集が可能な状態）には行の右下に「**✏️ 編集**」「**🗑 削除**」が表示され、**送信済みの品目**には「**🔒 SAP送信済のため編集できません**」と表示されます（変更するには受注の差戻しが必要、という案内がボタンの説明に出ます）。

**✏️ 編集（品目の修正・0円商品の差し替え）** — 行の「✏️ 編集」を押すと「**✏️ カート品目 編集**」画面が開き、**品番・品名（差替検索に使用）・単価（円）・数量・品目グループ**を修正出来ます。

画面下部の注意書きのとおり「**保存操作は「削除→追加」の2ステップで実行されます。SAPカートが CART / PENDING 状態のみ編集可能。**」です。

単価が0円のまま登録されてしまった商品を正しい商品へ置き替える時は、次の手順で「**🔄 差替候補**」を使います:

![カート品目 編集（差替候補の一覧から正しい価格の商品を選んで反映）](imgs/a97-cart-item-edit-replace.png)

| # | カート品目の差し替え手順 |
|---|---|
| 1 | 「品名（差替検索に使用）」欄に品名が入っていることを確認して「🔄 差替候補」を押す（空のままだと「品名を入力してください」） |
| 2 | 「🔄 「◯◯」の候補（◯件）- クリックで反映」として**0円以外の同名商品**の一覧（品番・品名・価格）が開く |
| 3 | 正しい候補をタップ → 「✅ 反映しました。「保存」を押すとSAPカートに適用されます」と表示され、入力欄に品番・品名・価格が入る |
| 4 | 「💾 保存」を押す → 「✅ 保存しました」。**保存の実体は「旧品目を外して新品目を入れ直す」置き替え**のため、保存後にパネルが開き直って最新のカートが表示されます |

> 候補が無い場合は「⚠ 該当商品が見つかりません」と表示されます。品番が空のまま保存しようとすると「品番は必須です」で止まります。
>
> **その場で金額を決める任意金額の商品は、この編集からは追加出来ません**（「任意金額の商品は編集からは追加できません。代理注文で追加してください」）。

**🗑 削除（品目の取り消し）** — 「🗑 以下の品目をSAPカートから削除しますか？」（品目名の一覧と「※ この操作は取り消せません」付き）の確認でOKすると「✅ カート明細を取り消しました」と表示されます。

**⚠ エラーになった明細だけを外す** — カート内の1品目だけがSAP側でエラーになる事があります（例: 保管場所に無い商品）。

エラーの明細には赤い「**⚠ この明細はエラーです: ◯◯**」のバナーと「**🗑 この明細を外す**」ボタンが付きます。

![エラー明細のバナーの表示例](imgs/a101-error-cart-item.png)

押すと「⚠️ エラー明細をSAPカートから外します。品目: ◯◯ エラー: ◯◯ この明細だけを削除します（他の明細は残ります）。よろしいですか？」の確認が出て、OKすると「✅ エラー明細「◯◯」をカートから外しました（理由: ◯◯）」と表示されます。

- **他の明細はそのまま残ります** — 外すのはエラーの1行だけです。
- 「⚠ 金額照合待ち」など**金額の照合が必要な状態の間は、このボタンは表示されません**（照合を解消してから操作します）。
- 外した後に正しい品目を入れ直す場合は、上の「✏️ 編集」または代理注文から追加します。

**🔁 予約からカート再構築** — カートが**空のときだけ**表示される復旧ボタンです。

押すと「🔁 予約からカート再構築 — 予約の品目をSAPカートに追加します。**既にカートに入っている品目コードはサーバ側で除外されるため、二重に積まれることはありません。** 続行しますか?」の確認が出て、実行すると「✅ カート再構築完了: ◯件追加」と結果が表示されます。

予約品目を後から手で追加しようとして既にカートにある場合は「⚠️ 予約からすでにカートに入っている品目があります — このまま追加すると同じ品目が2件になり、二重で請求されます。」の警告で止まるので、**意図した追加購入の時だけ**OKして下さい。

**🔍 SAP診断（注文ごとのSAP連携状態の確認）** — 画面のあちこちの案内文に出てくる「［注文詳細］→［SAP診断］で状態を確認してください」の確認場所です。

注文詳細パネルの中ほどにある「**🔍 SAP診断 (◯件) — 注文ごとのSAP連携状態**」の見出しを押すと開きます（普段は折りたたまれています）。

![SAP診断の表示例](imgs/a104-sap-diagnosis.png)

注文ごとに1枚のカードで、注文番号・注文の経路（line＝お客様のスマホ注文／代理＝代理注文／ゲスト）・SAP連携の状態・金額・紐付け情報・SAPへ送った日時が並びます。

状態の色付きバッジは、sent＝SAP登録まで完了（正常）、error＝SAP送信の失敗、cart_added＝カートへの蓄積までは成功、という意味です。

エラーの時は赤い「**エラー:**」枠に理由がそのまま表示されます。

- 「**↻ SAP再送**」は**SAP送信がエラーになった注文にだけ**表示されます（成立している注文への再送は二重投入になるため、ボタン自体が出ません）。
- 「**📋 診断コピー**」を押すと「✅ SAP診断をクリップボードにコピーしました」と表示され、そのカードの内容が文字でコピーされます。**エスカレーションの際はこれを貼り付けて共有**すると、口頭で読み上げるより速く正確です。
- 「📋 SAP送信ボディ」はSAPへ送った内容そのものの控えです。通常の運用で開く必要はありません — システム担当が原因を調べる時に使います。

#### 🏷 割引と業者キャッシュバック（詳しく）

割引とキャッシュバックは、名前が似ていますが**別の仕組み**です。取り違えると金額の説明を誤るため、先に違いを押さえて下さい。

| | 割引 | 業者キャッシュバック |
|---|---|---|
| 何に効くか | **お客様（喪主・葬儀社）の支払い額**が安くなります | 支払い額は変わりません。**葬儀社へ後から戻る金額**です |
| 画面での見え方 | 金額から差し引かれ、赤字の「🏷 割引合計」と内訳行で表示 | 支払い額の**下に黄色い破線の「💰 [別枠] キャッシュバック」枠**で表示（支払い額には含まれません） |
| 決まり方 | 窓口の「割引設定」で選んだ区分（区民葬・献体・減額・公費など）を基に**SAP側が金額を自動計算** | 葬儀社（得意先）ごとの条件でSAP側が計算。**値引き（割引）とは別の条件**です |
| 窓口での操作 | 「🏷 割引」で**支払い準備完了の前に**確定 | **窓口での操作はありません**（確認のみ） |

**割引の決まり方** — 窓口の「🏷 割引（割引設定）」で選ぶ区民葬・献体・減額・公費などの割引は、割引の画面にも説明が出るとおり「**手動割引と違い、予約の区分として登録します。金額はSAP側で自動計算されるため、登録後にSAPカートへの反映（予約品目の再投入）が必要です**」という扱いです。

つまり窓口で決めるのは「この予約にどの区分を適用するか」だけで、**いくら引くかはSAPが計算**します。

品目を入れた後に区分を変えた場合は品目の入れ直し（再投入）が必要になるため、割引は品目より先・遅くとも**支払い準備完了の前**に確定させて下さい。受注が確定した後は変更出来ません。

このほか、SAPの担当者が受注に直接入れた割引は、内訳の行に「**手動**」のバッジが付いて区別されます。

**割引を設定・解除した時に出る表示と対処**:

| 表示 | 意味と対処 |
|---|---|
| ✅ 割引区分をSAPカートへ反映しました（品目追加 ◯件） | 設定と同時にカートへの反映（品目の再投入）まで完了した正常終了です |
| 🚫 割引を解除しました | 「🚫 割引なし（解除）」の完了表示です |
| ⚠ 割引の設定は保存しましたが、SAPカートへ未反映です。「🔁 予約からカート再構築」を実行するまで金額に反映されません。 | 区分の保存だけ成功した状態です。**金額にはまだ効いていない**ため、案内どおり再構築を実行します |
| ⚠ 割引の設定は保存されましたが、カートの再構築に失敗しました／通信エラーが発生しました | 同上。「🔁 予約からカート再構築」をやり直します |
| ◯◯ はSAP中間側のカートフラグが未設定のため設定できません。（この状態で保存しても値引きは効きません） | この予約のカートが割引区分を受け取れない状態です。管理者経由でシステム担当へ連絡します |
| 割引設定の応答待ちがタイムアウトしました。サーバ側は処理を継続している可能性があります。 | **再操作せず**、受付カードを再読込して割引の状態を確認してから次の操作に進みます |

**割引の金額を確認できる画面は3つ**あります:

| 画面 | 開き方 | 分かること |
|---|---|---|
| 割引設定 | カードの「🏷 割引」 | 今どの割引区分が適用されているか・この葬儀社に使える区分 |
| 支払い内訳確認 | 「💰 支払い準備完了にする」 | 送信前の最終金額（支払者ごとの金額と品目グループ内訳） |
| 📋 注文詳細のSAP金額サマリー | カードの「▼ 詳細 → 📋 注文詳細」 | **確定後の割引の内訳と金額・キャッシュバックの[別枠]表示**（下で詳説） |

**📋 注文詳細「SAP金額サマリー」の読み方** — 受注確定後（SAP送信済み）の注文詳細には、緑色の金額サマリーが表示されます。上から順に読みます:

![注文詳細のSAP金額サマリー（割引内訳・[別枠]キャッシュバック・支払者別の請求明細・合計）](imgs/a92-order-detail-money-summary.png)

| 行 | 意味 |
|---|---|
| ✓ SAP受注確認 totals から表示 | この金額が**SAPの受注確認から取得した確定値**であることを示すバッジです |
| 金額（PPR0） | **割引前の本体価格の合計**。PPR0はSAP上の「本体価格」の記号です |
| 🏷 割引合計（赤） | 割引の合計。すぐ下に「└ 区民葬割引（10%） Z040 ×2品目 -¥410」のような**内訳行**が続きます（割引名・率・SAP上の記号・対象品目数・金額） |
| 税抜小計 → 📊 税額 | 割引後の税抜金額と消費税 |

**支払者別の請求明細** — サマリーの下には「💳 支払者別の請求明細」として、支払者（喪主=紫・葬儀社=青緑。売掛の葬儀社には「売掛」バッジ）ごとのカードが並びます。

各カードにはその支払者の**SAP受注番号・得意先コード**と、金額 → 割引（内訳付き）→ 税額 → 💰 支払い額が表示されます。

キャッシュバックの対象になる支払者（通常は葬儀社）のカードには、支払い額の下に[別枠]の黄色い枠が付き、内訳として「**└ Z050 業者バック(税抜)**」「**└ Z051 業者バック(税額)**」の2行が表示されます。

最後の濃い緑の「📊 合計」で、全支払者の支払い合計と「💰 [別枠] キャッシュバック合計」を確認出来ます。

**品目ごとの割引表示** — 割引が効いている品目は、明細の行でも分かります。元の金額に打ち消し線が引かれ、「🏷 -¥◯」の赤いバッジと割引後の金額が並びます。

行の下の「💳 SAP割引内訳」ボックスで、その品目1行分の 金額 → 割引（種別と率）→ 割引合計 → 税抜小計 → 税額 → 支払い額 を確認出来ます:

![品目行の割引表示（打ち消し線・割引バッジ・SAP割引内訳ボックス）](imgs/a93-order-detail-item-discount.png)

**キャッシュバックがある会計の進め方（よくある誤解と注意）**:

- 会計の操作は**通常とまったく同じ**です。振り分け → 支払い準備完了 → 精算QR → 会計完了、の流れにキャッシュバック用の操作はありません。

    「キャッシュバックがある時はQRを2回スキャンする」という案内が過去にありましたが、**誤案内**です。この件の精算機側の改修は**2026-09-25に検証環境へ反映済み**で、最終確認が進んでいます（→§6.3 Q9・§6.4）。

- キャッシュバックの金額は上記の[別枠]表示で**確認は出来ますが、窓口で金額を変える操作はありません**。金額に疑義がある場合はSAP側（本社経理）への確認になります。
- 自動精算機のロックには、精算のロックとは別に**キャッシュバックのロック**があります。「🔒 精算ロック管理」の解除対象に「キャッシュバックのみ」がある（⑪の表）のはこのためで、状態確認では両方のロック状態が表示されます。
- キャッシュバックの**帳票出力**が必要なケースで正しく出力されるかは、E2Eテストで継続確認中です（🔶確認中。帳票はSAP上「販売リベート請求書」として扱われ、出力検証が進行中です — §6.3 Q9）。

    また、セット商品の**値引き**条件が領収書明細に出ない事象の改修（§6.2）とキャッシュバック帳票は別の話です — 値引きとキャッシュバックは別条件として扱われます。

## 4. シナリオ別 操作フロー

実際の場面ごとに、誰が・どの画面で・何を押すかを纏めました。**全てのシナリオで、お客様にスマホの操作をお願いする場面はありません。** 画像は代表的な画面です（操作の詳細は第3章を参照して下さい）。

### シナリオA: 基本の流れ — 受付から会計まで（標準運用）

1. **【管理者・前日】** 「📅 予約」で翌日分を確定します（→§2.1）。
2. **【スタッフ・当日】** ご到着されたら「💳 お会計精算」のカードで「**✅ 受付する**」。喪主の行が「QR待ち」なら「**🖨 紙で受付**」も押します（→§2.3。火葬同意は紙のお手続き）。
3. **【スタッフ】** ご案内する控室・休憩室に「🚪 部屋紐付け」で予約を紐付けます。
4. **【スタッフ】** ご注文はお部屋・売店で伺い、「📝 代理注文」で入力します。オーダーのカードを「調理開始」→「提供済み」→ PDA計上 →「💳 お会計精算へ移す」と進めます。
5. **【スタッフ】** 「💳 お会計精算」で（🏷 割引・🏷 振り分け）→「💰 支払い準備完了にする」→ 支払い内訳確認で「💰 支払いお知らせを送信」→「🏧 精算QRを発行」→「🖨️ 印刷」で**《自動精算機ご利用票》を紙でお渡し** → 自動精算機でお支払い →「🏁 会計完了にする」。

> **このシナリオのつまずきどころ**: 通知が届かない前提の運用のため、**「お会計のご準備が出来ました」のご案内は必ず口頭で**行い、ご利用票のお渡しと合わせて精算機の場所をご案内します。
>
> また予約の確定（手順1）を受付より先に済ませておくこと — 順序が逆になると受注が二重に作られるケースがあります（§3.5）。

### シナリオB: 控室で喪主まとめ払い

1. **【スタッフ】** 「🚪 部屋紐付け」で控室・月の間1 に東博家の予約を紐付けます。
2. **【スタッフ】** お部屋で伺ったご注文を「📝 代理注文」で入力します（予約を選ぶため葬儀社払いで自動確定します）。
3. **【スタッフ】** 「調理開始」→「提供済み」→ PDA計上 →「→ お会計準備完了」。
4. **【スタッフ】** 「📋 注文詳細」で喪主払いにする品目の支払先を「喪主」に振り分けます（**代理注文は葬儀社払いで自動確定しているため、ここでの振り分けが必須です**）。**「お会計済み」は押しません。**
5. **【スタッフ】** 「💳 お会計精算」で 受付する →（割引）→ 支払い準備完了にする → 支払い内訳確認で「支払いお知らせを送信」→ ▼詳細 → 精算QRを発行 → ご利用票を紙でお渡し → 自動精算機でお支払い → 会計完了にする。

<img src="imgs/a10-room-assignments.png" width="360"> <img src="imgs/a51-assign-modal.png" width="360">

（左: 部屋紐付け ／ 右: 品目の振り分け）

> **このシナリオのつまずきどころ**: 手順4の振り分けを飛ばすと、喪主払いのつもりの品目が葬儀社払いのまま精算に進んでしまいます。
>
> LINEをお使いの場合と違ってお客様側から金額を確認する手段が無いため、**支払い内訳確認の画面の金額を、送信前にお客様へ口頭でお伝えする**と行き違いを防げます。

### シナリオC: 割引がある会計の例

| ケース | 内容 | 支払い | 操作の流れ |
|---|---|---|---|
| 例1 | 予約の火葬費用のみ | 葬儀社への請求（売掛） | 振り分けで「全て🏢 葬儀社（売掛）」→ 支払い準備完了。受注の行に「🧾 売掛のため精算不要」と出て、精算機は使わず月次請求で完結（→§3.7） |
| 例2 | 予約＋当日のご注文（代理注文）の合算 | 喪主と葬儀社で分割 | 振り分けで品目ごとに支払先を分ける → 支払い準備完了で受注が支払者ごとに分かれる → 受注ごとに精算QR（→§6.3 Q10の数字例） |
| 例3 | 当日のご注文（代理注文）複数明細 | 喪主 | 「全て👤 喪主」で一括振り分け → 喪主の受注1本にまとまる → 精算QRを1回発行 |
| 例4 | 社員割引の適用 | 葬儀社への請求 | 「🏷 割引」で該当の割引を適用してから支払い準備完了（割引はSAP側で自動計算。金額は支払い内訳確認で確認） |
| 例5 | 業者キャッシュバックあり | 葬儀社への請求 | 会計の操作は例1と同じ（キャッシュバック用の操作はありません）。金額は「📋 注文詳細」の黄色い「💰 [別枠] キャッシュバック」枠で確認。値引きとは別の条件で、帳票の出力は🔶確認中（→§3.7「🏷 割引と業者キャッシュバック（詳しく）」・§6.3 Q9） |

> **このシナリオのつまずきどころ**: 割引は**支払い準備完了より前**に確定させるのが鉄則です（受注確定後は変更出来ません）。
>
> 区分を選んだだけでは金額に反映されないケースがあるため、設定後のメッセージを必ず読み（「⚠ …SAPカートへ未反映です」なら案内どおり再構築）、「支払い内訳確認」で**割引後の金額になっているか**を目で確かめてから送信して下さい。
>
> 使える割引が出ない時は、この葬儀社の対応可否（得意先の設定）が原因のことが多いです（§3.8 得意先）。

（割引の適用画面。区民葬・献体・減額・公費は葬儀社ごとの設定に連動します）

### シナリオD: スポット注文（予約のないお連れ様のその場購入）

1. **【スタッフ】** 「📝 代理注文」で 斎場・売上場所を確認 →「🚶 予約なし」→ 購入者で「🚶 お連れ様」を選びます。お名前（任意）・領収書名を伺って入力します。
2. **【スタッフ】** 商品を選んで「**🚶 お連れ様購入（SAP即連携）**」を押します。

    この瞬間に**SAPへ受注が確定**し、「✅ お連れ様注文を作成しました 予約番号: G…」と表示されます（Gで始まるゲスト予約番号を控えておくと領収書・照会に便利です）。

3. **【スタッフ】** 「🍽️ オーダー」に現れたカード（「🧾 スポット注文（お会計精算の対象外）」バッジ付き・最初から「お会計準備完了」列）で商品をお渡しし、PDAで売上計上します。
4. **【スタッフ】** その場でお支払いを受けて「💰 お会計済み」を押して完結します。**「💳 お会計精算」タブには載りません**（お客様への通知もありません）。

> **このシナリオのつまずきどころ**: 通常の注文と違い、**送信＝受注確定**です。数量・商品を間違えたまま送ると受注の取り消し・修正が必要になるため、送信前の確認をより丁寧に行って下さい。
>
> 送信でタイムアウトが出た時は**再送する前に必ず注文一覧を確認**します（前回分が成立している場合、再送は自動で止まりますが二重投入防止の基本は目視確認です）。
>
> 酒類を含む場合は年齢・運転の有無の口頭確認をしてから確定します。

## 6. 困ったときは（Q&A）

**質問・不具合・要望の報告の仕方（2026-09-14 操作説明会で確認した運用）**

疑問や不具合らしき事象は、まず**QAシート**（操作説明会のQ&A・確認観点シート）へ記録し、内容を①**現行仕様の確認** ②**不具合候補** ③**追加要望** の3つに分けて整理してから、必要なものを課題管理（Backlog）へ起票します。

報告の際は、次の6点を出来る範囲で添えて下さい — **対象の予約番号／操作した画面／操作手順／期待した結果／実際の結果／画面キャプチャ**。その場で答えが出ないものは、曖昧に判断せず「要確認」として記録します。

**障害時の対応の目安（保守窓口・現在調整中の内容）**

| 項目 | 目安 |
|---|---|
| 障害受付時間 | 平日 10:00〜19:00（土日祝・年末年始を除く） |
| 一次応答 | 受付から24時間以内 |
| 復旧目標 | 重大（業務停止・全体影響）: 当日中に暫定対応、3営業日以内に恒久対応の方針提示 ／ 重要（一部業務停止・代替運用可）: 3営業日以内 ／ 軽微（表示の不具合など）: 10営業日以内 |

> 上記は保守契約に向けて調整中の水準です。確定後に改めて周知されます。

### 6.1 画面に出るメッセージと対処（管理画面）

**領収書の印字について確認済みの事実（2026-08-17 精算機の実機確認より）**:

- **セット商品は領収書に親の1行だけで印字**されます（例: 収骨容器の一式は「収骨容器（◯寸白壷 白覆一式）」1行）。

- セット商品の中にさらにセット商品が入る多段構成など、例外的な商品では構成品が残る可能性があります。気付いた場合は品目名を添えてシステム担当へ連絡して下さい。
- フリードリンク付き休憩室セットでの確認と、再発行の実機確認は追加確認の予定です。

### 6.3 現場からのご質問と回答（2026-09 操作説明会・QAシートより）

実際に斎場からいただいたご質問と、その回答・参照先を纏めました。「🔶確認中」の付いた項目は、開発・運用側で整理中の事項です。

回答は説明会当時（お客様のLINE操作を含む運用の前提）のものです — LINEのご利用を前提とする部分（通知・お客様のスマホ画面）は、使用しない方針の決定後は参考情報として読んで下さい。

**Q1. チェックイン前に予約内容（火葬日時・骨壺・休憩室・式場）を確認する方法は？**

管理者は次の手順で全て確認出来ます（→§3.5③）。

| # | 手順 |
|---|---|
| 1 | 「📅 予約」タブを開き、対象日と斎場を合わせて対象のご予約を表示する |
| 2 | 行の「✏️ 編集」を押す（**火葬日・火葬時間**は上部に表示されます） |
| 3 | 画面を下へ送る —「🏗 施設予約情報」で**式場・炉種別・時間帯**、「⚱ 収骨容器（骨壺）選択」で**骨壺**、「📦 予約品目」で**式場使用料・休憩室**などの品目を確認出来ます |
| 4 | 確認だけなら保存せずに閉じます（保存しなければ何も変わりません） |

<img src="imgs/a62b-rsv-edit-facility.png" width="420"> <img src="imgs/a62c-rsv-edit-items.png" width="420">

スタッフ権限の方は「📋 火葬確認」の一覧で、火葬開始時間・式場名/休憩室名・炉の種別・保管日数を確認出来ます（→§3.6）。

**Q2. 予約画面『編集』の使い方と、入力が反映される場所は？**

使い方は §3.5③ のとおりです。

保存すると即時に反映され、**入力した項目ごとに次の場所へ効きます**: 葬儀社の得意先コード → 代理注文の自動確定とSAP連携の支払先／割引フラグ（区民葬・献体・減額・公費）→ お会計精算の割引／📦 予約品目 → お客様の「予約カート」と会計時のSAPカート／氏名かな・電話番号 → 予約の検索・照合。

**Q3. 部屋紐付けに表示される喪家名の範囲は？ 通夜の追加貸しのデフォルト時間は変えられる？**

紐付け画面に出るのは「**当日の予約一覧**」です。通夜のご利用が予約データとして窓口へ届いていれば表示されますが、予約システムからの連携範囲（通夜予約を含むか）は 🔶確認中 です。

『部屋紐付けのデフォルト時間（分）』は「⚙️ 設定 → 初期設定」の「🚪 注文場所・部屋紐付け 設定」（§3.8に画像）にある**全体で1つの設定**で、**部屋ごと・ご予約ごとに変えることは出来ません**。

時間を延ばしたい時は、一度「解除」してから紐付け直すと残り時間がリセットされます（→§3.4③）。

**Q4.（TOHAKU-1752 確認1）フリードリンクを設定したのに、フリードリンク以外の商品も表示される**

フリードリンクの出し分けは「**FD対象品だけを残す**」仕組みでは**ありません**。

「対象外の飲み物（ソフトドリンク・アルコール・ノンアルコールのうちFD対象でないもの）を隠す」仕組みで、**軽食・和菓子などは表示されたままが正常**です。

そのうえで、出し分けが効く条件を順に確認して下さい（→§3.8）。

| # | 確認する場所 | 確認すること |
|---|---|---|
| 1 | ⚙️ 設定 → 🏛️ 斎場設定 → 対象の売り場 | 注文場所種別（SAP location）が「**休憩室（restroom）**」になっているか（**ラウンジは対象外**に変更されています） |
| 2 | 同じ売り場の「⚙ 設定」 | 「**フリードリンク予約に基づく出し分けを有効化**」がONか |
| 3 | 📅 予約 → ✏️ 編集 → 📦 予約品目 | ご予約に**フリードリンク対象の品目**（名称に判定文字「★」を含む）が入っているか |
| 4 | ⚙️ 設定 → 初期設定 → 🚪 注文場所・部屋紐付け 設定 | 「フリードリンク予約者に非表示にするMVGR1コード」に、隠したい飲料の分類が入っているか（**ここに入っていない分類は隠れません**） |

なお、フリードリンク表示ルールの**最終的な適用範囲は関係者間で合意の詰めが進行中**です（論点: ★判定の単位・FD対象と対象外が混在する予約の扱い・軽食の例外・代理注文への適用 — TOHAKU-1752/1897/1908・🔶確認中）。

上の表は現在の画面の動きで、合意の結果によって変わる可能性があります。

**Q5.（確認3）1つの売上場所に休憩室（restroom）と式場控室（waitroom）の両方を登録出来る？**

出来ません。**注文場所種別（SAP location）は1つの売上場所に1つ**です。休憩室と式場控室は**別々の売上場所として登録**して下さい。

種別を切り替えた後に部屋紐付けで控室が選べなくなった事象は、この種別変更の影響とみられます — 実際の画面での復旧手順は 🔶確認中（課題管理で対応中）です。

**Q6. CK状況が「済」でなくても予約確定は出来る？**

出来ます。確定と受付（チェックイン）は独立した操作です。むしろ**確定→受付の順が正しい順序**で、受付が先に済んだ予約を後から確定すると受注が二重に作られるケースが報告されています（対策改修中。→§3.5）。

**Q7. 代理注文の「お連れ様購入」は、通常の注文と動きが違う？**

違います。お連れ様購入（予約なし）は**送信した瞬間にSAPへ受注が確定**し、注文は最初から「お会計準備完了」列に入ります。

「💳 お会計精算へ移す」は出ず、オーダー画面内で「💰 お会計済み」まで完結させます（→§3.2「スポット注文の扱い」・シナリオD）。

**Q8. 喪家・葬儀社と関係のない代理注文は、予約に紐づかないデータとして精算する認識で合っている？**

概ね合っています。予約に紐付かないスポット注文としてSAPに**単独の受注**が立ちます。

ただし精算は「💳 お会計精算」ではなく**オーダー画面内で完結**させます（お会計精算の対象外バッジが付き、精算機用のQR発行の対象にもなりません。その場でのお支払いで「💰 お会計済み」にします。→§3.2）。

**Q9. キャッシュバック金額・割引金額を精算前に確認できる画面は？**

**割引**は、「🏷 割引（割引設定）」画面・「📋 注文詳細」・「💰 支払い準備完了にする」で開く「**支払い内訳確認**」画面で精算前に確認出来ます（→§3.7「🏷 割引と業者キャッシュバック（詳しく）」）。

**キャッシュバックの金額**も窓口で確認出来ます。

「📋 注文詳細」のSAP金額サマリーに、支払い額（税込）とは別の黄色い「**💰 [別枠] キャッシュバック**」枠で表示されます（SAPがキャッシュバックを返した会計のみ。支払い額からは引かれません。→§3.7）。

ただし表示されるのは受注確定後（支払い準備完了の後）のため、**精算前の時点ではSAP側の条件登録の確認**になります。

キャッシュバックの**帳票**は、SAP上は「**販売リベート請求書**」として扱われ、その出力検証が進行中です（TOHAKU-628。売掛の業者キャッシュバックを含む支払いパターンの検証も並行中 — TOHAKU-739）。

帳票が必要なケースで正しく出力されるかは引き続き 🔶確認中 の扱いです（なお**値引きとキャッシュバックは別の条件**として扱われます — §6.2）。

このほかキャッシュバックの周辺では、「2回QRスキャン」誤案内に対する**精算機側の改修が検証環境へ反映済み**です（2026-09-25・最終確認中 — TOHAKU-1821）。

あわせて、次の整理・対応が進んでいます（→§6.4）。

- キャッシュバックのみのお会計での**0円支払QR**の扱いの整理（1614・整理済み）
- **現金払いと売掛が混ざる場合**の受注登録方法（1616・検証環境反映済み）
- 複数式場品目の構成品目へのキャッシュバック金額の反映（1829・確認中）
- 条件付き30%キャッシュバックへの対応（1685・対応中）

**Q10. 分割精算（業者が午前に先払い・喪家が午後に来場して残りを支払う）の手順は？**

§3.7「💴 支払いを分けたいとき」の4手順がそのままこのケースです。

①「🏷 振り分け」で業者払いの品目と喪家払いの品目を分ける → ②「💰 支払い準備完了」（ここで受注が支払者ごとに分かれる）→ ③午前中に**業者の受注だけ**「🏧 この受注の精算QR」で入金し、午後に喪家の受注をQR発行して入金 → ④全ての入金が済んだら「🏁 会計完了にする」。

カードの「支払先ごとの受注」枠（→§3.7の画像）で、どの受注が支払い済みかを1行ずつ確認しながら進められます。

**数字を入れた例**（火葬料金¥59,000=業者払い・菓子/飲料¥5,260=喪主払いの場合）:

| 時間帯 | 操作 | 画面の状態 |
|---|---|---|
| 午前（業者来場） | 「🏷 振り分け」で火葬料金の品目グループを「🏢 葬儀社（現金）」、菓子・飲料を「👤 喪主」に割り当て →「✅ 振り分けを確定」 | 集計に「🏢 現金: ¥59,000 / 👤 喪主: ¥5,260」と表示 |
| 午前 | 「💰 支払い準備完了にする」→ 内訳確認 →「💰 支払いお知らせを送信」 | 受注が2本に分かれる（例: 783=葬儀社¥59,000・785=喪主¥5,260） |
| 午前 | 業者の受注783の行で「🏧 この受注の精算QR」→ 精算機でお支払い | 783の行が「✅ 支払済み」に変わり、785は「⏳ 未払い」のまま |
| 午後（喪家来場） | 喪主の受注785の行で「🏧 この受注の精算QR」→ 精算機でお支払い | 785も「✅ 支払済み」に |
| 午後 | 「🏁 会計完了にする」 | 会計完了列へ移り、会計が締まります |

**Q11. 会計完了後に注文ミスに気付いた場合の修正手順は？**

**お支払い（入金）前**なら、「← 会計待ちに戻す」で戻してやり直せます（精算処理の進行中は「🔒 精算未受付に戻せません」と表示され戻せません）。

受注確定後は振り分け・割引の変更は出来ないため、先に受注を戻す操作が必要です（管理者へ相談）。

**入金まで済んだ後**の取消・返金・再会計は、SAP側の受注取消を伴うため窓口画面だけでは完結しません — 正式な手順は 🔶確認中（管理者経由でシステム担当へご連絡下さい）。

関連して、**精算確定済みの伝票への品目の追加登録**（分骨壺・証明書の追加購入など）の動作確認も進行中です（TOHAKU-1865・🔶確認中）。

**Q12. 精算後の領収書の宛名変更のやり方は？**

**お支払い前**であれば、カードの「支払先ごとの受注」枠にある「**✏ 領収書宛名**」で受注ごとに宛名を変更出来ます。

**お支払い後**は紙が発行済みのため窓口からは変更出来ず、**中間システムの領収書画面からの再発行**になります（→§3.7）。

なお、精算機が印字する領収書の**宛名の出し分けの正式ルール**（どの支払者の時に誰の宛名になるか・葬儀場住所の取得元）は、東京博善様側で確認中の項目です（TOHAKU-822・🔶確認中）。

**Q13. 梅の間の予約を椿の間で紐付けても良い？ 精算はどちらの部屋になる？**

紐付け自体は可能です（部屋紐付けは「どの部屋のQRから注文出来るようにするか」を決める操作で、予約と別の部屋にも紐付け出来ます）。

**お部屋の利用料金は、紐付けた部屋ではなく予約品目（式場使用料・休憩室料）に基づいて請求**されます。

部屋の変更で料金も変える必要がある場合は、予約側（📦 予約品目）の修正が必要です（休憩室料金の明細への反映はE2E継続確認中 — §6.2）。

**Q14. モバイルオーダーの30分は喪家ごとに変えられる？ 3時間貸しでは短くない？**

**喪家ごと・部屋ごとの個別設定は出来ません**（既定時間は全体で1つの設定です — Q3参照）。長いご利用では、一度「解除」して紐付け直すと残り時間がリセットされるので、これで延長する運用になります。

標準時間そのものの見直し（例: 3時間貸しに合わせる）は全斎場・全部屋に効く変更のため、要望として課題管理（Backlog）へ起票して下さい。

**Q15. 式場利用で通夜がある場合も、チェックインして紐付けする？**

仕組みとしては「部屋のQRから注文する時間帯には紐付けが必要」「受付（チェックイン）は火葬当日の会計の起点」です。通夜の時間帯の運用（誰がいつ紐付けるか・受付を伴うか）は 🔶確認中 です。

**Q16. コーヒーラウンジでも部屋の紐付けは必要？ LINE前提？ 注文出来ない商品がある？**

必要です。**部屋なしで常時注文できるのは売店だけ**で、ラウンジを含むその他の売り場は紐付けが必要です（→§3.4）。ご注文は全て代理注文で承ります。

ラウンジで一部の商品が出ないのは、**注文場所種別による出し分け**（ラウンジ=軽食・デザート等）と、売上場所の『商品設定』による絞り込みの結果で、設定どおりの動きです（→§3.8・Q18）。

なお、ラウンジ利用時にどの品目を使うか（SAP側の品目整理）は運用課題として整理中です（TOHAKU-1260・🔶確認中）。

**Q17. 新式場の利用で、火葬中に別のお部屋を貸した場合も紐付けは必要？**

必要です。貸したお部屋のQRからご注文いただくためには、そのお部屋への紐付けが要ります（原則: 売店以外のお部屋のご利用は全て紐付け）。

なお、**長期貸し（サブスク契約）の式場・保棺室**の扱い（対象部屋の範囲・契約中の予約の売上対応）は別途整理中の項目です（TOHAKU-1242・1122・🔶確認中）。

10月に長期貸し保棺の式場が増える予定もあるため、該当施設の運用は整理結果を待って確認して下さい。

**Q18. 設定 → 斎場設定 → 売上場所管理 →『商品設定』の意味は？**

その売上場所で**販売する商品を選ぶ画面**です。「🍽️ ◯◯ の販売商品」が開き、**チェックを入れた商品だけ**がその売り場のメニュー（代理注文の商品一覧）に載ります。

注文場所種別（SAP location）による自動の出し分けとは別の、**売り場単位の手動の絞り込み**です:
