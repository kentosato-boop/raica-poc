## 1. システム全体の繋がり

「東京博善の窓口（mado）」は、**東京博善株式会社**の7斎場（**町屋斎場・落合斎場・代々幡斎場・四ツ木斎場・桐ヶ谷斎場・堀ノ内斎場・お花茶屋会館**）で、葬儀当日の**受付・火葬同意・飲食などの注文・会計精算**をデジタル化するシステムです。

**繋がっているシステム**

| 相手 | 何をやり取りするか |
|---|---|
| 新予約システム（テコテック製・9月稼働。旧 Fellow／タイコウ） | 毎朝、当日の火葬予約データを受け取る（中間サーバー経由） |
| LINE | お客様のミニアプリ・友だち追加・注文/提供/会計の通知・リッチメニュー |
| SAP（基幹システム・広済堂 情報システム部管理） | 商品カタログを受け取り、注文を「受注」として登録。割引（社員割・区民葬など）や仕訳も自動処理 |
| 自動精算機（東芝テック／ユニコ） | 管理画面で発行する「精算QR」を読み取り、お客様が支払い |
| PDA（スタッフ携帯端末） | 売上計上に使用 |
| アフターケアCRM「喪主の窓口」（§3.10） | 葬儀翌日以降、LINEメニューがアフターケア用に自動で切り替わり、法要・相続などのご案内に繋がる。ご遺族対応はコールセンター向け画面「喪主の窓口」（架電リスト・LINEチャット・チケット）で管理 |
| 会員情報登録API（OutSystems） | 火葬予約の会員情報を外部システムへ登録する連携（§3.9の「🧾 会員情報登録API 送信先」で送信のON/OFFと送信先を管理。連携OFFの間は呼び出されません） |

**一つ一つのシステムの役割（詳しく）**

**① 新予約システム（テコテック製）** — 火葬予約の大元です。窓口はここから**中間サーバー経由で予約データを受信するだけ**の参照側で、窓口の「📅 予約」タブから新規予約を作ることはありません（作成・変更は予約システム側で行い、窓口へは10〜15分程度の時間差で届きます — §3.5）。届いた予約を「確定」することで、受付・精算に使えるようになります。

**② 中間サーバー（NURVE管理）** — 窓口とSAP・予約システムの間に立つ通訳役です。商品カタログ・カート・受注・精算機の入金連絡は全てここを経由します。SAPへの送信がタイムアウトした時に「届いたかは不明」という表現になるのは、窓口→中間→SAPの2段構えのため、途中まで届いている可能性があるからです（だからこそ**再送の前に注文一覧・カートの確認**が必要になります）。

**③ SAP（基幹システム・広済堂情報システム部管理）** — 商品マスタ・得意先マスタ・受注・請求の正本です。窓口の商品・得意先・割引可否・受注ブロックは全てSAPから同期した写しで、**金額の最終的な正はSAP側**にあります。画面の金額とSAPの金額が食い違うと「⚠ 金額照合待ち」などで会計が止まる仕組みです（§3.7）。

**④ 自動精算機（東芝テック／ユニコ）** — 精算QR（SAP受注番号入り）を読み取ってお客様が支払う機械です。支払いが完了すると中間サーバー経由で窓口に入金の連絡が届き、受付と注文が自動でお会計済みに進みます。処理が途中で止まった場合は15分で自動解除され、急ぐ時だけ「精算ロック管理」を使います（§3.7⑪）。

**⑤ LINE（ミニアプリ・公式アカウント）** — お客様との接点です。ミニアプリ（申込・注文・履歴・料金確認・館内案内図）と、公式アカウントのトークに届く通知（注文の進行・支払いお知らせ＋精算QR画像・お支払い完了）、リッチメニュー（受付用⇄アフターケア用の自動切替）で構成されます。**LINEに紐付かない注文（スポット注文・紙で受付した喪主様）には通知が届きません** — その分は口頭と紙でご案内します。

**⑥ PDA（スタッフ携帯端末）** — 売上計上の端末です。窓口とは直接繋がっておらず、「PDAで計上してから『💳 お会計精算へ移す』を押す」という**操作の順序**で整合を取ります。

**⑦ アフターケアCRM「喪主の窓口」（Bluememe）** — 葬儀翌日以降のご遺族対応の画面です。窓口の会員情報（葬儀日）を起点にLINEメニューが自動でアフターケア用へ切り替わり、以降のやり取り（架電・LINEチャット・資料請求）はこちらで管理します（§3.10）。

**番号の呼び分け（取り違えの多い3つ）**

| 番号 | どこで使うか |
|---|---|
| **予約番号** | 新予約システムから届く番号（例: TEST-2500200 / 25087953）。管理画面の検索欄は**全て「予約番号」表記**です。注文カードでは 🔑 のマークで表示されます |
| **SAP受注番号** | 「💳 お会計精算」で「💰 支払い準備完了」を押したときにSAPが発行する番号（例: 783）。**精算QRはこの番号で発行**されます |
| **受付番号** | ①事前同意の受付番号（例: 260804-0001。管理画面「📋 事前同意」で発番）と、②当日の受付番号（例: #1。お客様のミニアプリのホーム画面に表示）の2種類があります |

**運用の要点**

- 予約・注文・受付の画面は**リアルタイム更新**です（新しい注文が入ると通知音が鳴ります）。
- SAPへの連携は**2段階**です。①「🍽️ オーダー」で注文を **お会計準備完了** に進めると（ボタンは「💳 お会計精算へ移す」）、SAP側の**カートに蓄積**されます（カードに「🛒 カート蓄積済」と表示）。②「💳 お会計精算」で **💰 支払い準備完了にする** →「支払い内訳確認」→ **💰 支払いお知らせを送信** まで進めた時点で、**SAPの受注（受注番号）が発行**されます。
- お客様のスマホからの注文送信は、応答まで**最大45秒**かかることがあります（**その間に再送信しないで下さい** — 二重請求の原因になります）。時間がかかるとお客様の画面には「⚠️ 通信に時間がかかっています。注文は受け付けられている可能性がありますので、もう一度送信せず「注文履歴」で状態をご確認ください。」と表示されます。
- 検証環境（STG）は**テスト専用**です。実際のお客様のデータは入れません。テストデータは予告なくリセットされることがあるため、確認結果は都度スクリーンショット等で保存して下さい。

## 2. 業務の全体像 — 前日の準備／当日の運用

この章では、火葬日前日までの準備と火葬当日の運用を、時系列に沿って説明します。各手順の詳しい操作方法は第3章（管理画面）・第4章（お客様の画面）を参照して下さい。

### 2.1 前日の準備（火葬日前日までの流れ）

担当: 葬儀社（QR配布）→ 申込者（喪家）→ 本社・斎場管理者

**1.【葬儀社】事前同意QRの配布** — 商談時に「事前同意QR」（全申込者共通）を申込者へ配布します。※新予約システム移行後は、SMSでリンクを直接送る方式に変更予定です。

**2.【申込者（喪家）】LINEでのお申込み（→§4.1）** — LINEでQRを読み取り、TOP画面（「お手続きは火葬日前日の17時まで」）から「申込にすすむ」→ 公式LINEの友だち追加 → 申込者情報の入力 → 規約への同意 → 送信、と進みます。完了画面「火葬の申込を受付させていただきました。」が表示され、「閉じる」でトーク画面に戻ります。

**3.【システム（自動）】予約との自動紐付け** — 翌日の予約取込時に、申込と予約の「**電話番号・故人名かな・火葬日・斎場**」の4点が全て一致した場合に、事前同意と予約を自動で紐付けます（2026-09-14 説明会周知の条件。表記のゆれは自動補正され、該当が1件に絞れた場合だけ成立します）。1つでも一致しない場合は自動紐付けされません。また予約側に火葬日・斎場・故人名・申込者名（かな）のいずれかが欠けていると照合自体が出来ず、「📋 火葬確認」に「照合項目不足」と表示されます。

**4.【管理者】予約の確定（→§3.5）** — 「📅 予約」タブで翌日分を確認し、「未確定」ボタンから確定します（区民葬・献体・減額・公費の該当と得意先を確認。確定済みは「✅確定」表示）。

**5.【スタッフ】未紐付けの手動紐付け（→§3.8）** — 「📋 事前同意」タブで未紐付けの申込を確認し、自動で一致しなかった分を手動で紐付けます。

**6.【スタッフ】未同意者の事前確認（→§3.6）** — 「📋 火葬確認」の日付を翌日に切り替え、「⚠ 未承諾のみ」で未同意の方を抽出します。必要に応じて事前連絡や受付票の印刷を行います。

### 2.2 当日の運用（火葬当日の流れ）

担当: 斎場スタッフ（受付・炉前・売店・配膳）

**① 始業前チェック（→§3.1）** — 通知音ON／表示日付=本日／斎場=自斎場を確認し、画面を最新に更新します（Ctrl+Shift+R）。

**② 火葬同意の確認（→§3.6）** — 「📋 火葬確認」で本日の予約一覧（火葬開始時間順）を確認します。「承諾」（緑）→ そのまま火葬進行。「未承諾」（赤）→ ③へ。

**③ 炉前で当日取得（→§3.6・§4.2）** — 該当行の「QR」で受付QRをお客様に提示 → お客様が読み取り → TOP画面で「📋 ご登録内容（故人様）」を確認 →「申込にすすむ」→ 火葬同意・利用規約に同意 → 申込者情報を入力して「入力して受付へ進む」。※ご予約のあるお客様は「あとで入力する」を選べず、その場で全項目の入力が必要です。※喪主様がLINEをお使いでない場合は、「💳 お会計精算」のカードから「🖨 紙で受付」（LINEなし受付）が使えます（§3.7①-2）。

**④ 部屋の紐付け（→§3.4）** — 「🚪 部屋紐付け」で控室・休憩室の部屋に予約を紐付けます。紐付けするとその部屋のQRから注文出来るようになり、フリードリンクの出し分けも有効になります。

**⑤ 注文対応（→§3.2・§3.3）** — お客様のスマホ注文とスタッフの「📝 代理注文」を、「🍽️ オーダー」で 未処理 →（調理開始）→ 調理中 →（提供済み）→ 提供済み →（PDA計上 →）お会計準備完了 と進めます。※代理注文でご予約を選んだ場合、購入者は「葬儀社払い」で自動確定します。喪主様のお支払いにする時は「📋 注文詳細」で支払先を振り分けます。

**⑥ 精算（→§3.7）** — 「💳 お会計精算」で 受付する →（割引・振り分け）→ 支払い準備完了にする → 支払い内訳確認 → 支払いお知らせを送信（ここでSAPの受注番号が発行）→ ▼詳細 → 精算QRを発行 → 自動精算機でお支払い → 会計完了にする、と進めます。喪主まとめ払いはここで一括精算します。

**⑦ 利用終了（→§3.4）** — 部屋の紐付けを「解除」します。LINEメニューは葬儀日の翌日に自動でアフターケア用へ切り替わります。

![⑤注文対応 — 4つの列で注文を進行管理](imgs/a01-orders-kanban.png)

**ヘッダーの働き（詳しく）**

- **斎場の切り替え** — 選べる斎場は自分のアカウントの「アクセス範囲（許可斎場）」の中だけです（管理者は全斎場）。切り替えると**全タブの一覧・件数・通知が選択中の斎場に連動**します。「一覧に出るはずのものが出ない」「件数が合わない」時は、まずここを確認して下さい（他斎場の注文はポップアップ通知も鳴りません）。
- **表示対象日** — オーダー・火葬確認などの一覧が対象日に連動します。日付を過去に切り替えて履歴を確認した後は、**必ず本日に戻して**下さい（戻し忘れが「注文が出ない」の定番原因です）。
- **リアルタイム更新** — 画面は自動で最新化され、ヘッダーに「**リアルタイム接続中**」と表示されます。通信が切れると「**❌ 接続エラー**」に変わりますが、**10秒後に自動で再接続**を試みます。表示が戻らない時だけ再読込（Ctrl+Shift+R）して下さい。

**🔍 一つ一つの操作の詳しい流れ（オーダー）**

**① 👨‍🍳 調理開始** — 調理が必要な商品（天ぷらそば・うどんなど温かい食事）を受けた時に、厨房へ取り掛かりの合図をするための操作です。押す前に、カードの商品明細と場所ラベル（どのお部屋からの注文か）を確認します。押すとカードが「調理中」列へ移るだけで、**お客様への通知は届きません**（調理中の通知は仕組みとしてありません）。飲み物だけの注文など、調理が要らない場合はこのボタンを押す必要はなく、次の「🍽️ 提供済み」へ直接進めて構いません。押し間違えた場合は「← 未処理に戻す」で戻せます。

**② 🍽️ 提供済み** — 商品をお客様のお手元へ届け終えた時に押します。押した瞬間にカードが「提供済み」列へ移り、**お客様のLINEに「🍽️ 注文 #◯ の提供が完了しました。」の通知が届きます**。つまりこのボタンは「お届け完了の連絡」を兼ねているため、**実際にお渡しする前に押さないで下さい**（お客様が「届いたはずの商品が無い」と混乱する原因になります）。複数の注文をまとめてお届けした場合は、届けた注文のカードを1枚ずつ押します。

**③ 💳 お会計精算へ移す** — お渡しが済んだ注文を会計の待ち行列に載せる操作で、**PDAで売上計上を済ませた後**に押すのが順番です。押すと2つのことが同時に起きます: (1) カードが「お会計準備完了」列へ移り、注文の内容が**SAPのカート（会計の入れ物）に蓄積**されます（受注番号はまだ発行されません — 発行は「💳 お会計精算」タブの「💰 支払い準備完了」で行われます）。(2) お客様のLINEに「💳 注文 #◯ のお会計の準備ができました。スタッフにお声がけください。」が届きます。この通知を見たお客様が個別にお支払いに来られることがあるため、**喪主まとめ払いのご家族では「お支払いは代表の方がまとめて行います」と一言添えて**下さい。なお、ご予約に紐づかないスポット注文ではボタン名が「💳 お会計準備完了」と表示されますが、働きは同じです。

**④ 💰 お会計済み** — 売店などで**その場で現金等のお支払いが完了した**注文だけに押します。お客様のLINEに「💰 注文 #◯ のお会計が完了しました。」が届き、カードは右上の「お会計済み」件数に集計されます。**喪主まとめ払いの注文では絶対に押さないで下さい** — まとめ払いは「💳 お会計精算」タブで一括精算するのが正しい流れで、ここで押してしまうと精算対象から外れてしまいます。また、SAPの金額確認が必要な注文では、このボタンの代わりに「⚠ SAP金額照合待ち」と表示されて押せません（§3.7の「🔄 SAPと照合」で確認してから進めます）。

**⑤ ← 戻すボタン（未処理に戻す／調理中に戻す／提供済みに戻す／お会計準備完了に戻す）** — 押し間違えた時に、カードを1つ前の列へ戻すための操作です。戻しても**既に送られたお客様への通知は取り消せません**（例: 提供済みを取り消しても「提供が完了しました」の通知は届いたままです）。戻した後は正しい順序でもう一度進めて下さい。

**⑥ ✕（注文の取り消し）** — 「未処理」列のカードにだけ付いています。注文そのものを取り消す操作で、押すとお客様のLINEに「❌ 注文 #◯ はキャンセルとなりました。」が届きます。調理が始まった後（調理中以降）の取り消しは、この✕ではなく「✏️ 編集」での一部取消か、列を未処理へ戻してからの取り消しになります。取り消しのご依頼をお客様から受けた場合もスタッフがこの操作で対応します（お客様の画面には取消ボタンはありません）。

**⑦ ✏️ 編集（一部キャンセル）** — 「1品だけ取り消したい」「数量を間違えた」時の操作です。開いた画面で行の「✕」を押すと合計金額がその場で再計算され、消し過ぎた時は「＋ 商品を追加」で商品名・品番から戻せます。最後に「保存」を押すまで確定しません。**編集出来るのはSAPカートへ入る前（お会計準備完了へ移す前）まで**で、投入後は「SAPカート投入後の注文は編集できません」と表示されます。その場合の内容変更は§3.7側（注文詳細・SAP照合）で扱います。

**⑧ 📋 注文詳細** — 予約番号の単位で、その方の全注文の明細・金額・支払先の振り分け・SAP連携の状況をまとめて確認する画面です。会計の前に「どの品目を誰が支払うか」を確認・変更したい時はここを開きます（振り分けの詳しい操作は§3.7）。確認だけなら何度開いても状態は変わりません。

**⑨ ↻ SAP再送・📋 送信内容・↻ 失敗分を一括再送** — SAP連携に失敗した注文（⚠SAP失敗の赤いバッジ）を送り直す操作です。押す前に必ずバッジにカーソルを合わせて**失敗理由の全文**を確認して下さい（例:「代表品目分類 "17" の支払割当が見つかりません」→ 先に振り分けを直さないと再送しても同じ失敗になります）。「📋 送信内容」ではSAPに送った内容そのものを確認出来ます。失敗が複数ある時は画面上部の「↻ 失敗分を一括再送」でまとめて再送できます。**「⚠ SAP未確定」（到達が確認できていない）の注文だけは、そのまま再送すると二重投入の恐れがある**ため、先に「📋 注文詳細」でカートの中身を確認してから判断して下さい。

**🧾 スポット注文の扱い（予約にも受付にも紐付かない注文）**

「🚶 予約なし」から入力した代理注文・お連れ様購入など、**予約にも受付にも紐付かない注文**は、通常の注文と会計の仕組みが根本的に異なります。

- **SAP連携のタイミングが違います。** 通常の注文は「お会計準備完了」でカートに蓄積→「💰 支払い準備完了」で受注確定、という2段階ですが、スポット注文は**ご注文を送信した時点で、その注文だけで完結する受注としてSAPへ確定**します（カートには積まれません）。
- **「💳 お会計精算」タブには載りません。** 受付単位で精算するお会計精算の対象外のため、カードに「**🧾 スポット注文（お会計精算の対象外）**」のバッジが付き、「💳 お会計精算へ移す」ボタン自体が表示されません（代わりに「→ お会計準備完了」が出ます）。
- **会計はこのオーダー画面内で完結させます。** お渡し・PDA計上の後、「→ お会計準備完了」→ その場でお支払いを受けて「💰 お会計済み」の順に進めます。
- **お客様への通知はありません。** LINEに紐付かないため、提供完了・会計完了などの通知は届きません。お渡しとお会計は口頭でご案内下さい。
- **お連れ様購入には「G」で始まるゲスト予約番号**が自動で発行され、カードと成功表示（「✅ お連れ様注文を作成しました 予約番号: G…」）に表示されます。領収書や後からの照会はこの番号で行えます。

**🔍 一つ一つの操作の詳しい流れ（代理注文）**

**① ⚙️ 斎場・売上場所設定（STEP 0）** — 「どこの売上として計上するか」を最初に決める操作で、ここが未選択の間は下のステップが全て塞がっています。売上場所（控室・売店・ラウンジなど）と保管場所（在庫の引き当て元）を選びます。毎回同じ場所で入力する方は「デフォルト保存」を押しておくと、次回からログインした時点で自動的に選ばれた状態になります。**売上場所を間違えたまま注文を送ると、後の精算でエラーになる**事例が報告されているため（誤った売上場所でも入力自体は通ってしまいます）、送信前にもう一度設定バーの表示を確認して下さい。

**② 🔍 紐付け（予約番号で選ぶ）** — 予約番号が手元にある場合の最短ルートです。入力して押すと、その場で予約が検索され、成功すると「✅ 予約紐付け完了: 東博　太郎」と表示され、紫のバッジ（予約番号・故人名・葬儀社名）が付きます。番号の打ち間違いなどで見つからない場合はエラーが表示されるだけで、何も確定しません。選び直したい時はバッジの「✕」を押します。

**③ 📋 予約一覧から選ぶ** — 番号が分からない時に使います。本日の予約が一覧表示され、故人名・葬儀社・予約番号で検索、葬儀時間順の並び替えが出来ます。行を選ぶとその予約に紐付き、②と同じ状態になります。受付（チェックイン）が完了している予約は、葬儀社の得意先が自動で入っています。

**④ 🚶 予約なし（スポット注文）** — ご予約と関係のないスポット購入（お連れ様の追加の飲み物など）の入り口です。これを選んだ時だけ「2 購入者を選択」が開き、**誰のお支払いになるか**を必ず選びます。葬儀社（→得意先の選択欄が開く。**売掛が使えない葬儀社では売掛の注文は送信前に止まります**）・喪主（直売）・お連れ様（SAP即連携＝その場精算）から選択します。**スポット注文は送信した時点でSAPへ受注として確定し、「💳 お会計精算」タブには載りません**（オーダー画面内で「→ お会計準備完了」→「💰 お会計済み」と進めて完結。§3.2「スポット注文の扱い」参照）。予約なしで送った注文は後から予約に紐付けられないため、ご予約のある方の注文と分かっている場合は必ず②か③で予約を選んでから進めて下さい。

**④-2 お連れ様購入の流れ（詳しく）** — 購入者で「🚶 お連れ様」を選ぶと、お名前・領収書名・ラベルを添えられます（お名前が未入力の場合は「お連れ様」で登録されます）。商品を選んで「**🚶 お連れ様購入（SAP即連携）**」を押すと、**その瞬間にSAPへ受注が確定**し、「✅ お連れ様注文を作成しました 予約番号: G…」と表示されます（**Gで始まるゲスト予約番号**が自動採番され、領収書やお問い合わせの手掛かりになります）。作成された注文は最初から「お会計準備完了」列に入るので、お支払いを受けて「💰 お会計済み」で完結します。送信中に通信が切れた場合は「送信の結果が確認できませんでした（通信タイムアウト）。SAPに届いたかは不明です。再送する前に必ず注文一覧を確認してください」と表示されます — **必ず注文一覧を確認してから**再送して下さい。前回の送信が実は成立していた場合は、再送時に「⚠ 前回の送信が既に注文として成立しています。注文一覧を確認してください」と自動で止まる仕組みも入っていますが、確認が先です。

**④-3 酒類を含む注文の記録** — ビール・日本酒など酒類を含む代理注文・お連れ様購入を確定すると、**職員が年齢と運転の有無を口頭で確認したものとして記録**されます（確認した職員のアカウントが監査記録に残ります）。必ず口頭確認をしてから確定して下さい（ノンアルコール商品は対象外です）。

**⑤ 商品を選んで「注文を送信」（STEP 3）** — 商品カードの「＋／−」で数量を調整すると、画面下部に合計金額が積み上がります。絞り込み（大分類・商品名・品番など）は表示を絞るだけで、カートの中身には影響しません。購入者によって出せる商品が自動で変わる点に注意して下さい: お連れ様には一般商品のみが表示され、喪家向け商品（精進料理膳など）やスタッフ代理専用品（骨壺など）は自動的に隠れます。購入者を途中で変更すると、その購入者に出せない品目はカートから外され、件数と理由が画面に表示されます。「注文を送信」を押すと確定し、「🍽️ オーダー」タブの「未処理」列に新しいカードが現れます（以降の進行は§3.2と同じです）。**送信は1回だけ**押し、応答を待って下さい（最大45秒。§1参照）。タイムアウトの表示が出た場合は「届いていない」と決めつけず、**先に注文一覧で前回分が入っていないかを確認**します — 同じ内容をもう一度送っても、前回が成立していた場合は「⚠ 前回の送信が既に注文として成立しています」と自動で止まる仕組みが入っています。

**⑥ 送信した後の支払先の直し方** — 予約ありの代理注文は自動的に「葬儀社払い」で登録されます。喪主様のお支払いにしたかった場合は、送信後に「🍽️ オーダー」の「📋 注文詳細」を開き、支払先を「喪主」へ振り分け直します（§3.2⑧・§3.7）。注文を送り直す必要はありません。

**① 紐付け** — 「この部屋を、今からこのご家族が使う」とシステムに登録する操作です。押すと「予約を紐付け」画面が開き、当日の予約一覧から**行そのものをタップ**した瞬間に確定します（「確定」ボタンはありません。タップ＝確定なので、行を選ぶ前に故人名・葬儀社名をよく確認して下さい）。確定した瞬間から、その部屋に貼ってあるQRを読み取ったお客様がメニューを開けるようになり、残り時間（既定30分）のカウントダウンが始まります。予約にフリードリンク対象の品目が含まれていれば、休憩室ではフリードリンクメニューが自動で表示されます。**既に別のご予約が紐付いている部屋**で行をタップすると上書きの警告が出ます — 前のご家族の利用が本当に終わっているかを確認してからOKして下さい。

**② 解除** — ご利用終了時に「この部屋は空きました」と登録する操作です。押すと「紐付けを解除しますか？」の確認が出て、OKすると即座に解除され、その部屋のQRからは注文出来なくなります。**解除を忘れても残り時間が切れれば自動失効しますが、失効するまでの間は次のご家族がその部屋から注文出来ません**。お見送りが済んだら忘れずに押す運用にして下さい。表示が「期限切れ」に変わった部屋では解除ボタン自体が消えます（もう解除する必要が無いためです）。

**③ 残り時間（ラストオーダー）の見方** — 各部屋の行に残り時間がカウントダウン表示されます。この時間がそのままラストオーダーとして働き、切れた後にお客様がQRから注文しようとすると「ただいまこのお部屋ではご注文いただけません」と表示されます。ご利用が長引く場合は、一度解除してから改めて紐付けると時間がリセットされます。標準の30分は「⚙️ 設定 → 場所・部屋設定」で変更出来ます（管理者のみ）。

**④ 再読込** — 他の端末で行われた紐付け・解除を含めて一覧を最新の状態にします。フロアの担当が複数いる時は、操作の前に一度押す習慣にすると行き違いを防げます。

**④ LINE申込を検索（予約→申込の紐付け）** — 「予約はあるのに、LINEで入力された申込がまだ紐付いていない」時に、この予約側から申込を探しに行く操作です。押すと画面上部に予約マスターの内容（参照のみ）が表示され、下の検索欄で受付番号・申込者かな・電話番号の**いずれか1項目だけでも**検索出来ます（部分一致）。**何も入力せずに検索**すると、「予約の故人名・火葬日・斎場が全て一致する未紐付けデータ」が候補に出ます。候補に付くバッジ（完全一致候補／相違あり／別予約に紐づけ済み）の意味は下の説明を参照し、**完全一致でも内容を目で確認してから**紐付けて下さい。逆方向（申込側から予約を探す）は「📋 事前同意」タブです（§3.8）。

**⑤ 🔍 検索・再読込** — 検索は故人名・申込者・電話・予約番号での絞り込みです（ひらがな・カタカナはどちらでも一致します）。再読込は他の端末での受付・同意の進みを含めて一覧を最新化します。炉前対応の直前には一度再読込してから状況を確認して下さい。

**「LINE連携 / 申込紐付け」列は上下2段のバッジ**で、それぞれ別のことを表します。

| バッジ | 見ているもの |
|---|---|
| **✅ LINE連携済** ／ LINE未連携（上段） | このご予約に**お客様のLINEアカウントが繋がっているか**（受付QRの読み取りや事前のご登録が済んでいるか） |
| **申込紐付済** ／ **申込未紐付**（下段） | **LINEで入力された火葬申込（事前同意のデータ）がこのご予約に紐付いているか** |

<img src="imgs/c-link-badges.png" width="260"> <img src="imgs/c-link-badges-linked.png" width="260">

（左: LINE未連携＋申込未紐付 ／ 右: ✅ LINE連携済＋申込未紐付）

2つは独立しているため、「✅ LINE連携済」なのに「申込未紐付」という組み合わせも普通に起こります。①事前にLINEで申込をしたが名前の表記ゆれなどで自動紐付けされていない（→「LINE申込を検索」で紐付け）、②当日QRからその場で同意・受付をした（事前の申込データ自体が無いのでこの表示のままで正常。「火葬同意」列が「承諾」なら対応不要）、のどちらかです。

喪家名の下に「**照合項目不足**」と出ている行は、LINEでのお申込みと突き合わせるための項目（**火葬日・斎場・故人名・申込者名〈かな〉**のいずれか）がご予約側に足りていないため、**事前同意の自動紐付けが出来ません**。この行は「📋 事前同意」タブで手動の紐付けが必要になります（バッジにカーソルを合わせると不足項目が表示されます）。自動紐付けの条件そのもの（電話番号・故人名かな・火葬日・斎場の4点一致）は §3.8 を参照して下さい。

> 「🏁 会計完了にする」で会計が完了すると、お客様のLINEに「**✅ お支払いが完了しました。ご利用ありがとうございました。またのご利用をお待ちしております。**」の通知が届き、お客様のLINEメニューが受付後のメニューに切り替わります。

**会計カードの進み方（受付〜支払いまで）**

| 今の状態 | 大きいボタン | 補助（常時） | 「▼ 詳細」の中 |

| 受付前（会計待ち列） | ✅ 受付する | 🏷 割引（葬儀社受付では 🏷 振り分け・📋 注文詳細 も） | 🗑 完全削除 |
| 受付済み | 💰 支払い準備完了にする（→ 支払い内訳確認 → 💰 支払いお知らせを送信） | 🏷 割引・🏷 振り分け・📋 注文詳細 | ← 精算受付に戻す・🗑 完全削除 |

**🔍 一つ一つの操作の詳しい流れ（お会計精算）**

**① ✅ 受付する** — ご来場を受け付けて、この方の会計を「会計待ち」の列に載せる操作です。押す前にカードの喪家名・葬儀社名・火葬同意バッジ（承諾/未承諾）を確認します。押すとカードが会計待ちに並び、以降の割引・振り分け・精算の起点になります。誤って受付した場合は「▼ 詳細」の「← 精算未受付に戻す」で戻せます（**「💰 支払い準備完了」を押す前まで**）。

**①-2 🖨 紙で受付（喪主がLINEを使えない時）** — カードの喪主の行（👤）には、喪主様のLINE連携の状態が「✅ LINE連携済」または「QR待ち」で表示されます。**「QR待ち」のまま（＝喪主様がQRを読み取れない・LINEをお使いでない）場合は、紫の「🖨 紙で受付」ボタン**が出ます。押すと「喪主を紙で受付します。（LINEなし）続けますか？」の確認が出て、OKすると**LINEなしで喪主様の受付が完了**し、以降の会計（振り分け・精算QR・ご利用票の紙渡し）を通常どおり進められます。LINEに紐付かないため、この方への通知は届きません — お声がけと紙のご利用票でご案内下さい。

**② 🏷 振り分け（品目振り分け）** — 「どの品目を誰が支払うか」を決める操作で、**「💰 支払い準備完了」より前に済ませておくのが原則**です。開いた画面で品目グループごとに支払先（葬儀社〈現金〉・葬儀社〈売掛〉・喪主・**💰 直売**）を割り当てます。「💰 直売」を選んだグループには**直売得意先コード（数字6〜10桁）の入力欄**が開き、未入力のままだと画面下の集計に「⚠ 直売得意先コード未入力◯件」と表示されて確定出来ません。売掛が使えない葬儀社では「🏢 葬儀社（売掛）」の選択肢自体が表示されません。画面下の集計（👤 喪主 ¥◯ / 🏢 現金 ¥◯ / 🏢 売掛 ¥◯ / 💰 直売 ¥◯）で金額の割れ方を確認してから確定します。全品目が同じ支払先なら上部の一括ボタン（「全て👤 喪主」「全て🏢 葬儀社（現金）」「全て🏢 葬儀社（売掛）」）が最速です。割り当てたら必ず「✅ 振り分けを確定」（画面によっては「💾 振り分けを保存」）を押して下さい — 未保存の間は「✏️ 未保存の変更があります」と表示され、保存すると「✅ 振り分けを保存しました」と出ます。「未設定」のまま送信すると**葬儀社払い〈現金〉として扱われ**、SAP側に既に支払割当があるカートでは登録に失敗します。**受注が確定した後は振り分けの変更は出来ません**（ボタンが押せなくなり理由が隣に表示されます）。

**③ 🏷 割引（割引設定）** — 区民葬・献体・減額・公費の割引を適用する操作です。開くと現在の割引と選べる選択肢が表示されます。選択肢は**葬儀社（得意先）ごとの対応可否と連動**しており、使える割引が無い葬儀社では「割引種別が見つかりません」と表示されます。適用済みの割引を外す時は「🚫 割引なし（解除）」を押します。割引は金額の根拠になるため、**支払い準備完了の前に**確定させて下さい。

**④ 💰 支払い準備完了にする（支払い内訳確認 → 💰 支払いお知らせを送信）** — 会計の中心となる操作です。押すと確定前に「**支払い内訳確認**」画面が開き、葬儀社払い（現金）と喪主支払い（現金）の金額・合計（税抜）・品目グループ内訳・警告が表示されます。ここで金額が想定どおりかを必ず確認し（警告が出ている場合は下の警告一覧表に従って先に解消）、「**💰 支払いお知らせを送信**」で確定します。確定した瞬間に、(1) **SAPに支払者ごとの受注番号が発行**され、(2) お客様のLINEへ「💰 お待たせいたしました。お支払いの準備が整いました。…」の本文と**精算QRの画像**が届き、(3) カードの大きいボタンが「🏁 会計完了にする」に変わって「▼ 詳細」の中に精算系のボタンが現れます。内訳が違っていた場合は「🏷 振り分けを変更」からやり直せます（送信前まで）。

**⑤ 🏧 精算QRを発行** — お客様が自動精算機でお支払いになるためのQRを画面に出す操作です（「▼ 詳細」の中・SAP登録成功後に表示）。税込金額が確定している受注は緑色で金額とQRが表示され、「精算QRを発行（税込 ¥◯◯）」で確定します。税込金額を確定出来ない受注では黄色の警告が出て発行出来ません（先に「🔄 SAPと照合」）。発行後は「🖨️ 印刷」で《自動精算機ご利用票》（A4・QRとお支払金額入り）を印刷してお渡し出来ます。**売掛の受注はここには出ません**（自動精算機の対象外・月次のご請求書で回収）。

**⑥ 📩 支払いQRを再送** — お客様のLINEに届いた精算QRが見つからない・消してしまった時に、同じQRをもう一度LINEへ送る操作です。最初の送信がLINE連携の不調で失敗していた場合も、LINE連携・友だち追加を確認してからこのボタン（または同じ「💰 支払いお知らせを送信」）で再送するだけで済みます（受付の状態は「支払い準備完了」のまま進んでいます）。

**⑦ 🧾 支払確認** — 自動精算機でのお支払いが済んだかどうかをその場で照会する操作です。精算機からの入金の連絡は通常自動で届きますが、「お客様は払ったと仰っているのに画面が変わらない」時に手動で確認出来ます。

**⑧ 🏁 会計完了にする** — お支払いの確認が取れた後に押す締めの操作です。押すとカードが「会計完了」列へ移り、**お客様のLINEに「✅ お支払いが完了しました。ご利用ありがとうございました。またのご利用をお待ちしております。」が届き、お客様のLINEメニューが受付後のメニューへ自動で切り替わります**。「⚠ 金額照合待ち」「⚠ SAP照合待ち」が表示されている間は押せません — 先に「🔄 SAPと照合」等で解消します。押した後に誤りに気付いた場合は「← 会計待ちに戻す」で戻せますが、精算処理の進行中は「🔒 精算未受付に戻せません」と表示されます。

**⑨ 🔄 SAPと照合／↻ SAP再送** — 「🔄 SAPと照合」は、画面の金額とSAPの受注金額・割引条件を突き合わせて食い違いを解消する操作です（⚠金額照合待ち・⚠SAP照合待ち・精算QRの金額不一致の時に使います）。「↻ SAP再送」はSAP連携をやり直す操作で、**「⚠ SAP到達不明」の状態では先に「📋 注文詳細」でカートの内容を確認してから**再送して下さい（そのまま再送すると二重投入の恐れがあります）。SAP照合の結果入力は管理者（superadmin）の権限が必要です — スタッフの画面では案内が表示されるので管理者へ連絡して下さい（§6）。

**⑩ 🧾 領収書分割（受注分割へ）** — 領収書を分けたい時の**案内**を開くボタンで、分割そのものはこの画面では行いません。開くと対象のSAP受注番号と「🔀 受注分割やり直し画面を開く」ボタンが表示され、分割は外部の受注分割やり直し画面で行います。既に分割済みの場合のみ「🗑 分割を解除して領収書1枚に戻す」で画面から戻せます。分割やり直し画面のURLが未登録の場合は管理者に「⚙️ 初期設定 → SAP連携設定」での登録を依頼して下さい。

**⑪ 🔒 精算ロック管理** — 自動精算機が処理の途中で止まった時の非常用の操作です。**15分経てば自動解除される**ため、通常は待つだけで構いません。急ぐ場合のみ、「外部受注ID（予約番号など）」と「得意先コード」の2つを入れて「🔍 状態確認」→ 解除対象・理由・斎場コードを選んで「🔓 ロック解除」の順で使います。SAP受注番号しか分からない時の「SAP受注番号で直接解除」は状態を確認しないまま解除する最終手段なので、**別の端末で精算中でないことを必ず確かめてから**実行して下さい。

**🔒 精算ロック管理の使い方**（精算機で処理が中断し、15分の自動解除を待てないときだけ使用）

![精算ロック管理に外部受注IDと得意先コードを入力した状態](imgs/a72-lock-filled.png)

| # | 操作 |
|---|---|
| 1 | 「外部受注ID」に予約番号などを、「得意先コード」（例: 900000）を入力して「🔍 状態確認」 |
| 2 | 状態が表示されたら、**解除対象**（精算のみ／キャッシュバックのみ／精算・キャッシュバック両方）・**理由**（通信断で残留／誤操作／その他）・**斎場コード**（例: YT）を選び、必要に応じて理由の詳細を記入 |
| 3 | 「🔓 ロック解除」を押す |

> SAP受注番号しか分からない場合は「**SAP受注番号で直接解除**」に進めますが、この場合はロック状態を確認しないまま解除することになります（画面にも「⚠ ロック状態は確認できていません」と表示されます）。**別の端末で精算中でないことを必ず確認してから**実行して下さい。
>
> 精算機が途中で止まった場合は15分で自動解除されます。二重会計防止のため、精算機側での二重操作はしないで下さい。

**🔍 一つ一つの操作の詳しい流れ（事前同意）**

**① 状態の絞り込みと検索** — 初期表示は「未紐付け」（＝手動対応が必要な申込だけ）です。「全て」「紐付け済み」にも切り替えられます。検索は受付番号・氏名・かな・電話・住所など全項目の部分一致で、ひらがな・カタカナはどちらで入力しても一致します（例:「とうはく」でも「トウハク」でも東博様がヒット）。まず未紐付けで一覧を出し、電話や受付番号で対象を特定するのが基本の流れです。

**② 紐付け（申込→予約の方向）** — 対象の申込の行で「紐付け」を押すと紐付け画面が開き、火葬予約を検索して候補が表示されます。候補には「完全一致候補」（緑）または「要修正」のバッジが付きますが、**一致していても自動確定はされません** — 火葬日・斎場・故人名・申込者名を目で確認してから選択して下さい。

**③ LINE申込を編集して紐づける** — 候補を選んだ後、申込内容の確認・訂正画面に進みます。名前の表記ゆれ（旧字体・スペースの有無など）が自動紐付けを妨げた原因であることが多いため、ここで予約側の表記に合わせて直します。**氏名・電話・住所・続柄は空に出来ません**（空にすると保存でエラーになります）。

**④ 変更して紐づけを完了する** — 最後の確定操作です。押すと紐付けが保存され、**申込者のLINEへ紐付け完了の通知が届きます**。この保存と紐付けは何度実行しても結果が変わらない（安全にやり直せる）操作ですが、**「LINE通知だけ再実行」だけは押した回数分の通知が届く**ため、通知が未達と確認できた時以外は押さないで下さい。

**⑤ 紐付けが出来ない・切り替えられない時** — 候補に「別予約に紐づけ済み」と表示される申込は、既に他の予約と繋がっています。また既に別のLINE申込と紐づいた予約への切り替えは出来ません（「この予約は既に別のLINE申込と紐づいているため切り替えできません」）。この場合はどちらの紐付けが正しいかを予約内容で確認し、誤っている側の扱いを管理者と相談して下さい。

## 5. シナリオ別 操作フロー

実際の場面ごとに、誰が・どの画面で・何を押すかを纏めました。画像は代表的な画面です（操作の詳細は第3章・第4章を参照して下さい）。

### シナリオA: 売店でその場支払い

1. **【お客様】** 売店のQR（ラベル「売店レジ前」）を読み取り、瓶ビール（中瓶）等を注文します（売店は部屋紐付け不要で常時ご注文いただけます）。
2. **【スタッフ】** すぐ渡せる商品なので「🍽️ 提供済み」を直接押します（LINEに提供完了通知）。
3. **【スタッフ】** 商品を渡す → PDAで売上計上 →「→ お会計準備完了」。
4. **【スタッフ】** 現金を受け取り「💰 お会計済み」（LINEに会計完了通知）。

<img src="imgs/m-order-menu.png" width="220"> <img src="imgs/c-order-card.png" width="360">

（左: お客様の注文メニュー ／ 右: スタッフ側に現れる注文カード）

> **このシナリオのつまずきどころ**: 「💰 お会計済み」を押してよいのは**その場でお支払いが完了した時だけ**です。「後でまとめて」と言われたらこのボタンは押さず、シナリオBの流れ（お会計精算での一括精算）に切り替えます。また「提供済み」を押した時点でお客様に通知が届くため、お渡しと同時に押すのがコツです。

### シナリオB: 控室で喪主まとめ払い

1. **【スタッフ】** 「🚪 部屋紐付け」で控室・月の間1 に東博家の予約を紐付けます。

## 7. 困ったときは（Q&A）

**質問・不具合・要望の報告の仕方（2026-09-14 操作説明会で確認した運用）**

疑問や不具合らしき事象は、まず**QAシート**（操作説明会のQ&A・確認観点シート）へ記録し、内容を①**現行仕様の確認** ②**不具合候補** ③**追加要望** の3つに分けて整理してから、必要なものを課題管理（Backlog）へ起票します。報告の際は、次の6点を出来る範囲で添えて下さい — **対象の予約番号／操作した画面／操作手順／期待した結果／実際の結果／画面キャプチャ**。その場で答えが出ないものは、曖昧に判断せず「要確認」として記録します。

**障害時の対応の目安（保守窓口・現在調整中の内容）**

| 項目 | 目安 |
|---|---|
| 障害受付時間 | 平日 10:00〜19:00（土日祝・年末年始を除く） |
| 一次応答 | 受付から24時間以内 |
| 復旧目標 | 重大（業務停止・全体影響）: 当日中に暫定対応、3営業日以内に恒久対応の方針提示 ／ 重要（一部業務停止・代替運用可）: 3営業日以内 ／ 軽微（表示の不具合など）: 10営業日以内 |

> 上記は保守契約に向けて調整中の水準です。確定後に改めて周知されます。

| 「未承諾のみ」で件数が減った | 絞り込みが ON の状態。もう一度押すと全件表示 |
| 予約の件数が合わない | 表示は選択中の斎場のみ。右上の斎場を確認 |
| かなで検索しても出ない | ひらがな/カタカナはどちらでも可。出ない場合はふりがな未登録の可能性 |
| 「検索対象が上限に達しています」 | 火葬日または斎場で絞ってから再検索 |
| 「精算QR発行」ボタンが見当たらない | 「支払い準備完了」を押して SAP 登録が成功すると「▼ 詳細」の中に現れる |
| 精算機が途中で止まった | 15分で自動解除。急ぐ場合のみ「精算ロック管理」で状態確認・解除（精算機側で二重操作しない） |
| 「支払割当が見つかりません」等のSAPエラー | 画面を最新に更新（Ctrl+Shift+R）→ 支払先を振り分け直す → 「↻ 失敗分を一括再送」。繰り返す場合はシステム担当へ |
| お連れ様の注文がエラー表示なのに登録されている | 表示の既知不具合。SAP受注番号の記録を優先し、二重登録しない |
| 注文送信が長い | 最大45秒かかることがあります。**再送信しない**（二重請求防止） |
| LINE通知が届かない | 友だち追加・通知設定を確認（ブロックと通知オフは別物） |
| QRが読めない | 汚れ→再印刷。**部屋QRと精算QRの取り違え**も確認 |
| 誤って受付した | 「💳 お会計精算」でカードの「▼ 詳細」→「← 精算未受付に戻す」。**「支払い準備完了」を押す前まで**しか戻せません |
| 在庫の一覧が空のまま | 斎場と**保管場所**を選んでから「📥 在庫取得」を押します（保管場所が未選択だと取得出来ません） |
| 予約に葬儀社（得意先）が入っていない | この画面では直さず、予約の連携元と得意先マスタを確認 |
| 予約を登録・更新したのに画面に出ない | 予約システムからの反映には**10〜15分程度**の時間差が出ることがあります。少し置いて再読込（§3.5） |
| 注文画面に関係のない商品まで表示される | 売上場所マスタの**注文場所種別（SAP location）が未設定**だと全商品が表示されます。「⚙️ 設定 → 🏛️ 斎場設定」で設定を確認（§3.9） |
| スポット注文を「お会計精算へ移す」ボタンが無い | 仕様どおりです。予約に紐付かない注文はご注文時にSAPへ受注確定済みのため、お会計精算の対象外（カードに「🧾 スポット注文」バッジ）。オーダー画面で「→ お会計準備完了」→「💰 お会計済み」と進めます（§3.2） |

**対応中の既知事象（2026-09-14 操作説明会で共有。改善が入るまで下記を確認して下さい）**

| 事象 | 現場での確認ポイント |
|---|---|
| 注文を取消した後も、精算検索に古い受注番号が残る場合がある | 注文取消後は、**取消済みの注文が精算対象として残っていないか**を「💳 お会計精算」で確認する（取消成功分の関連データを同期削除する改修が進行中） |
| 受付後に予約確定を行うと、同じ受注が二重に作られる場合がある | 予約確定→受付の順を守り、確定後に「💳 お会計精算」の一覧へ**同じ方のデータが二重表示されていないか**を確認する（§3.5） |
| 休憩室・フリードリンクセットなど**セット商品の値引き条件が領収書明細に出ない**場合がある | 明細への反映改修が進行中。なお**値引きとキャッシュバックは別の条件**であり、割引の明細表示とキャッシュバック帳票は同じものとして扱いません |
