## 2. 手順書の構成方針（ユーザー要望の履歴で確定したルール）

1. **章構成**: 1 システム全体のつながり → 2 業務の全体像（前日Ver./当日Ver.）→ 3 管理画面 → 4 LINEミニアプリ → 5 シナリオ → 6 権限 → 7 Q&A。**「システム概要」章は置かない**（手順書なので）。**付録（リスク台帳・用語集・出典・検証記録）は v6.1 で削除**（先方連携に不要とのユーザー指示。全文は git 履歴のコミット `b9d3393` にある）。
2. **本文は業務言語のみ**。ファイル名（admin.html等）・画面ID・関数名・API・開発課題番号は本文に書かない（リスク台帳・出典は付録扱いで課題番号可）。
3. **各画面は「できること → ボタン画像つきの説明表 → 操作手順」**の形式。ボタン名は実画面の表記と一字一句合わせる。
4. **スクリーンショットはすべて最新画面**（旧ダークテーマ・旧レイアウトは使用禁止）。LINEミニアプリは実際に操作した画面。**LINE画像の表示幅は 340px**（`<img width="340">`）。
5. 固有名詞は業務のもの（7斎場名・幕内祭典などのテスト葬儀社・東博太郎などのテスト人名・受注番号 TEST-2500200・区民葬/献体/減額/公費・精算QR 等）を積極的に使う。
6. 認証情報（パスワード・APIキーの値）は本文にも画像にも絶対に載せない（機械チェック済みの状態を維持）。
7. **火葬同意（§4.1/4.2）はお客様目線の導線形式**（2026-08-05 大沼様要望）: STEP番号つきで「何を見て・何をタップし・次に何が出るか」を書き、**トーク画面⇄ミニアプリの行き来**（友だち追加でLINEの画面へ移動／事前同意完了の「閉じる」でトーク画面に戻る）を導線図（imgs/j-flow-*.png、tools/flow_diagram.html から生成）＋実画面で明記する。同意画面のボタン表記は「**次へ進む**」（「同意して進む」ではない）。**「最新版です」等のメタ文言・撮影日の注記は本文に書かない**（テストデータである旨の一言のみ可）。ボタン・部品画像は撮影後に必ず目視検証する（v6.2でフッターメニューの切り抜きが壊れたままクライアントに見えた事故あり）。事前同意の完了画面に受付番号は表示されない（番号は管理画面「📝 事前同意」側に発番）。

## 3. 対象システムの要点（調査済みの事実）

- 東京博善の窓口（mado）: 7斎場（町屋・落合・代々幡・四ツ木・桐ヶ谷・堀ノ内・お花茶屋会館）向け。検証環境 `https://mado-staging.web.app/`・本番 `https://madoguchi-ec1d5.web.app/`。開発リポジトリは GitHub `nurveteam/mado`。
- 体制: 東京博善（小島室長・大沼様・榎本様）／広済堂 情シス（SAP）／NURVE（一次請け・中間サーバー: 山本様）／ARCRA（PM）／rubyjobs（Mario Yi 氏→2026-08引き継ぎ）／テコテック（新予約）／Bluememe（CRM）／東芝テック・ユニコ（精算機）。
- 管理画面のタブ: オーダー／代理注文／部屋紐付け／予約（管理者のみ）／火葬確認（旧・受付。9列テーブル）／お会計精算（会計待ち/会計完了の2列＋精算ロック管理）／事前同意／設定▾（初期設定・会員・商品・在庫〈故障中〉・得意先・斎場設定・ユーザー・QR発行）。
- LINEミニアプリ: TOP（前日・当日とも「申込にすすむ」／当日は対象者〈故人〉の情報を表示）→同意→申込者情報→受付→注文→履歴/予約カート/料金確認。エンディングノートはフェーズ2で現在封鎖中（プレビューURLのみ）。**手順書には掲載しない**（古い印刷QRの話も書かない — 2026-08-05ユーザー指示）。
- 重要な運用注意: 喪主まとめ払いは「お会計済み」を押さない／注文送信は最大45秒・再送信禁止／「本日分クリア」はUAT期間中非表示／部屋QRと精算QRは別物。
- スケジュール: Phase1 リリース判定 8/7・運用引継ぎ 8/9。受入テスト 8/1〜8/17・判定ステコミ 8/20・リリース 9/1。

## 4. スクリーンショットの撮影方法（再現手順）

**制約: この作業環境から `mado-staging.web.app` への直接アクセスは組織のネットワークポリシーで遮断**（403）。そのため実ソースをローカルで起動して撮影する方式を確立済み。

1. **ソース入手**: Google Drive に mado リポジトリのミラーがある。**毎回 `title = 'admin.html'` で検索し、modifiedTime が最新のものを使うこと**（v7.1 は 2026-08-05 08:31 更新版で検証。8/4版とは約34KBの差があり、必須項目・精算ロック・SAP状態表示が変わっていた）。Drive 検索「title = 'admin.html'」で最新の `public/admin.html`（約900KB）と `index.html` をダウンロードし、`tools/public/` に置く（**リポジトリにはコミットしない**。別プロジェクトのソースのため）。
2. **モックサーバー起動**: `python3 tools/mock_server.py`（ポート8787。テストデータ: 東博太郎/幕内祭典/TEST-2500200等・日付はJSTで当日に自動設定）。
3. **撮影**: Playwright＋同梱Chromium（`/opt/pw-browsers/chromium-1194/chrome-linux/chrome`）で
   - `tools/capture.py` 管理画面の基本＋LIFFプレビュー
   - `tools/capture2.py`〜`capture4.py` 斎場選択後のフロー・モーダル類
   - `tools/capture6.py`〜`capture7.py` SAP失敗状態・設定系
   - `tools/capture_liff.py` LINEミニアプリ実フロー（開発モードで LIFF 不要。撮影時に DEV バッジを自動非表示）
   - `tools/capture8.py`／`capture9.py` ボタン・部品の要素単位撮影
   - 仕組み: Firebase/LIFF/QRコード/Leaflet/xlsx の外部ライブラリはスタブ注入、API はモックサーバー応答、Firestore リスナーはモックデータを直接流し込む。
4. **画像最適化**: 幅1400px（ボタンは900px）へ縮小し、250KB超はパレット256色化。
5. **HTML/PDF生成**: `tools/build_manual_html.py` で単一HTML（画像は data URI 埋め込み。`![...]()` と `<img src="imgs/...">` の両方に対応）→ Playwright の `page.pdf()`（A4・print_background・ヘッダー/フッター付き。印刷用CSSで h2 改ページ・画像分割防止）。
