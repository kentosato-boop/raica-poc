# 数値トレーサビリティ（想定値と実測を取り違えないために）

作成日: 2026-07-26 ／ 目的: 画面・仕様書の数字が「実績」なのか「想定（モック）」なのかを一目で区別する

> **結論を先に**: 現時点でリポジトリに現れる業務数値は、ごく一部（テスト件数など検証可能なもの）を除き、**ほぼすべて想定値（仕様書に基づくモック）**です。PoC 本番の実測で置き換える前提で設計されています（`docs/ロジック仕様書.md §9`）。対外資料で「実績」と言い切らないでください。

---

## 1. 区分の凡例

- 🟢 **検証済み**: リポジトリ上で実際に確認できる事実
- 🟡 **想定値**: 仕様書定義に基づくモック。PoC 実測で置換予定
- 🔵 **ベースライン**: 比較の基準として置かれた前提値（要出典確認）

## 3. 検算できるもの（仕様書内で辻褄が合う）

ロジック仕様書 §6 の数値は、定義から再計算して一致することを確認できます（＝内部整合はしている。ただし**実測ではない**）。

- 推薦→成約 展開率: `22 / 128 = 17.2%` ✔
- 両側判断済み: `26 + 29 − 22 = 33 ≤ 34`（両側待ち1名）✔
- DB内訳: `6,180 + 19,842 + 4,192 = 30,214` ✔

> 「辻褄が合う」＝**モックとして矛盾がない**という意味であり、**現場実績を測ったものではない**点に注意。

## 4. 日付のズレ（デモの正史 vs 現在）

- デモデータの「正史」は **2026-07-17（金）基準**（ロジック仕様書 §7）。個別候補者のタイムライン（例: Hoa 様の内定提示 7/14）はこの固定シナリオ上の話です。
- ロジック仕様書・未決事項リストの発行日は **2026-07-19**。
- 現在は **2026-07-26**。→ 画面の「今日の状態」はデモ日付に固定されているため、**実日付と読み替えない**でください。

## 5. 使うときのルール

1. 対外資料に数値を載せるときは、この表の区分（🟢/🟡/🔵）を必ず添える。
2. 🟡 想定値を「実績」と言い換えない。「仕様に基づく想定。PoC で実測」と注記する。
3. PoC で実測が出たら、この表の該当行を 🟢 に更新し、`docs/未決事項・リスクリスト.md` の該当番号を消し込む。
