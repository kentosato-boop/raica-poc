# 東京博善案件 連携設計（構造的に、ヌケモレなく回すための型）

作成日: 2026-07-26 ／ 目的: 勝さん・畑澤さんが加わった体制で「誰が・何を・いつ・どこで」を迷わず回す

---

## 0. 連携の考え方（3層で分けると漏れない）

情報と行動を **3層** に分けて置き場所を固定します。これが混ざると連携が崩れます。

| 層 | 中身 | 置き場所（正） | 誰が触るか |
|---|---|---|---|
| **記録系（SoR）** | 候補者・求人・選考の正本データ | Porters | Porters 運用者・RA/CA |
| **行動系（SoA）** | 今日誰に何をするか／マッチ・キュー・接触ログ | RAiCA アプリ | RA / CA |
| **合意・設計** | 仕様・意思決定・リスク・本パッケージ | Git リポジトリ（`docs/`） | 案件メンバー全員 |

> 迷ったら「これは記録か／行動か／合意か」で仕分ける。連絡や口頭決定を**合意層（docs）に必ず戻す**のがヌケモレ防止の要。

---

## 1. 役割と責任（RACI）

`R`=実行 / `A`=最終責任 / `C`=相談 / `I`=共有。**氏名欄は `【要確認】`**（勝さん・畑澤さんの担当はここで確定してください）。

| 活動 | RA担当 | CA担当 | PdM/リード | 法務 | Porters窓口 | 勝さん | 畑澤さん |
|---|---|---|---|---|---|---|---|
| 東京博善との窓口・合意形成 | | | A | C | | 【要確認】 | 【要確認】 |
| PoC 成功条件の合意・週次レビュー | C | C | A/R | I | | 【要確認】 | 【要確認】 |
| RAiCA 開発・改修 | I | I | A | | | 【要確認】 | 【要確認】 |
| Porters 連携（契約プラン・同期） | C | | A | | R | 【要確認】 | 【要確認】 |
| 数値の実測・KPI 更新 | R | R | A | | C | 【要確認】 | 【要確認】 |
| コンプライアンス（PDPL/Zalo）確認 | | | A | R | C | 【要確認】 | 【要確認】 |
| 候補者・企業への実連絡（HITL 送信） | R | R | I | C | | | |

> **まず埋めるべきは「勝さん」「畑澤さん」の列と、各行の `A`（最終責任者）**。A が空欄の行は「誰も責任を持っていない＝落ちる行」です。

## 2. 意思決定の権限と記録（Decision Log）

決めたことを**必ず1か所に残す**。口頭・チャットで決めても、下記テンプレで `docs/` に戻す。

```md
### DL-001 | 決定日: YYYY-MM-DD
- 論点:
- 決定内容:
- 決定者（A）:
- 根拠／代替案:
- 影響を受ける未決事項番号（未決事項・リスクリスト #）:
- 次アクションと期日:
```

- 決定が**未決事項リスト**の項目に対応する場合は、その番号を必ず紐付ける（例: `#12 休眠配信の適法性`）。
- 決定の**変更**は上書きせず追記（DL-001 → DL-001-rev1）。履歴を残す。

## 3. カデンス（定例のリズム）

| 会議 | 頻度 | 目的 | 入力 | 出力 |
|---|---|---|---|---|
| PoC 週次レビュー | 週1 | 成功条件3点の進捗を実測で確認 | `02_数値トレーサビリティ.md` の実測欄 | Decision Log 追記・遅れの原因特定 |
| オープン事項レビュー | 週1（レビューと同枠でも可） | 未決37項目のオーナー・期日を前進 | §4 のトラッカー | 期日更新・エスカレーション |
| 引き継ぎ同期 | 随時 | 属人化の解消・不在時の代替 | §5 の引き継ぎマップ | 代替担当の確定 |

> 会議体そのものより、**「入力ドキュメント → 決定 → docs に戻す」の一巡が毎回回ること**が重要。

## 4. オープン事項トラッカー（オーナーと期日を持たせる）

未決事項・リスクを「放置しない」ための最小トラッカー。優先5項目を初期投入。**オーナー・期日は `【要確認】`**。

| # | 事項 | 種別 | オーナー | 期日 | 状態 | メモ |
|---|---|---|---|---|---|---|

| #28/#11 | 数値の出所（実測 vs 想定） | 品質 | 【要確認】 | 【要確認】 | 一部整理済 | → `02_数値トレーサビリティ.md` |
| #20 | Porters 書き戻しフロー | 連携 | 【要確認】 | 【要確認】 | 未着手 | CSV 往復の図が必要 |
| #21/#35 | LLM/インフラ コスト概算 | コスト | 【要確認】 | 【要確認】 | 未着手 | 1通単価×通数＋固定費 |

## 6. エスカレーション経路

```text
現場（RA/CA・開発）
   │ 判断できない／期日リスク
   ▼
PdM/リード（A：最終責任）
   │ 案件方針・対外・法務に関わる
   ▼
勝さん / 畑澤さん（【要確認】：役割に応じて）
```

- **止血が先、原因は後**: 送信誤り・データ流出の疑いは、まず配信停止（Porters 即時反映）→ 監査ログ確認 → Decision Log。
